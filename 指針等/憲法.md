# 経験DB運用憲法

## 目的

たかの経験を、まず事実として記録・蓄積する。  
価値判断・選別は後から行う。

## AI協働体制（現在）

経験DBは、**たかを中心に、バドと協働して運用する**。

- **たか**＝実際に経験する・試す・使う・判断する・最終的に決める
- **バド**＝たかと協働し、必要に応じて過去ログの発掘・整理、設計、分析、提案、EXP/RECの整理、GitHubへの書き込み、ID管理、文章化、実装、検証などを担う
- **JUN / Claude / その他のAI・ツール**＝必要な場合に使う補助的な手段。固定担当・必須工程ではない

過去にJUNやClaudeが特定の作業を担当した記録は、当時の作業履歴として扱う。現在の固定役割として解釈しない。

**たか＋バドだけで経験DBや関連作業を完結できる場合、それでよい。**

## 重要原則

- 迷ったら、まず記録する。
- 経験を価値や重要度で格付けしない。価値判断・選別は後から行う。
- RECは発生した順に時系列で積み上げる。既存RECを書き換えて過去を修正しない。
- 過去ログの発掘・整理は、たかとバドが必要に応じて行う。
- 既存RECは変更・削除しない。訂正・追加が必要な場合は、新しいRECとして記録する。
- 事実と推測・解釈を分ける。AIが推測・解釈した内容を、たかの経験や事実として記録しない。
- たかが実際に経験・発言した事実を、AIが創作・補完してはならない。不明な場合は不明のまま扱う。
- EXP/RECのIDは「ID管理台帳」のルールに従う。
- 経験ログの作成・更新、GitHubへの書き込み、ID管理・台帳更新は、作業時点の状況に応じてたか＋バドで実施する。特定のAIを固定担当とはしない。
- **直チャットを登録すると決めた場合、直チャットは要約・編集せず、原文そのものを保存する。**
- **直チャットを受け取ったら、まず生ログとして保存し、その後に既存EXPの確認とEXP/REC化を行う。**
- **基本フローは「たかが中心 → バドと一緒に考える → 必要な作業を実行する」とする。**ただし、作業内容に応じて順序や担当は柔軟に変えてよい。
- AIが利用できないことを前提にしても経験DBの運用が止まらない構造とする。
- AIの役割は実運用から学び、必要に応じて現在資料を更新する。

## 画像の扱い

画像は経験DBやプロジェクトそのものではない。

物理状態・外観・画面状態など、テキストだけでは十分に伝えにくい情報を補助するために使う。重要な事実を画像だけに依存しない。

## 過去資料との関係

過去の「3者体制」「JUN担当」「Claude担当」等の記述は、当時の運用を知るための履歴として残す。現在の基本認識は `BUD.md`、`docs/AI_READ_MAP.md`、`docs/00_CURRENT_STATE.md` と現在のrules/projectsを優先する。
