# REC-0000000020

## 所属EXP
EXP-0000000050

## タイトル
インタビューを異常対応だけでなくポジティブな価値発見にも広げ、会話制御として機能させる

## 発生日
2026-09-14

## 概要
インタビュー機能を「問題発生時・作業停止時の情報不足を補うもの」に限定すると、たかの成功・発見・肯定的評価を経験資産として拾えないことを確認した。また、既存ルールを追加しているのに行動が変わらない原因として、ルールが説明文・チェック項目に偏り、入力イベントに対するトリガー→必須行動→完了条件→検証の制御構造が弱かったことを確認した。

## 1. 発生したこと

たかから、インタビューはネガティブなトリガーだけではなく、「これはよかった」「このやり方は使える」「これは面白い」「思ったよりうまくいった」「これは今後も使いたい」「JUNのこの提案はよかった」等のポジティブな思いも残したい、という要望が示された。

同時に、過去の実例としてJUNからの提案に対し、把握・理解・案作成・提案まで進めるべきところで何もしなかった問題を振り返り、ルールを増やしても実際の行動へ結びつかない原因を確認した。

## 2. 確定した判断

- インタビューは「作業停止時だけ」の機能ではない。作業中でも、たかの評価・判断・実感・発見を取りこぼすおそれがあれば起動対象とする。
- 強いネガティブ評価・意思疎通異常は、原則として自律作業を止め、短いインタビューへ切り替える。
- ポジティブ評価は機械的に聞き返さず、何がよかったか・なぜよかったか・今後どう使えそうかが既に明確なら追加質問しない。曖昧で再利用価値がある場合だけ短い価値発見インタビューを行う。
- JUN等の外部提案は、**把握 → 理解 → 採否判断 → 案作成 → たかへ提案 → 実行 → 検証**までを必須の行動系列として扱う。「確認しました」で終了しない。
- ルール追加時は、**トリガー → 必須行動 → 完了条件 → 検証例**を定義する。文章量の増加だけをルール有効化と扱わない。
- 既存ルールが機能しなかった場合は、同じ文言を追加するのではなく、トリガー・必須行動・優先順位・完了条件・検証方法のどこが弱かったかを原因として確認する。

## 3. 今回の意味

経験DBに残す対象は、失敗や問題だけではなく、成功・有用性・面白さ・再利用価値も含む。さらに、AI運用ルールは「知識の説明」ではなく、実際の入力に対して確実に行動を起動し、完了を検証できる制御構造として設計する必要がある。
