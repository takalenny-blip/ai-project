# REC-0000000150

## 基本情報

- EXP-ID: `EXP-0000000030`
- REC-ID: `REC-0000000150`
- テーマ: DiMORA取得方式の検討における「検証環境」と「最終運用環境」の混同防止
- 日付: 2026-09-09

## 背景

認証済みDiMORAページを安全にプログラム取得する方式についてJUNへレビューを依頼した。JUNは、既に取得実績のあるWindows + Chromeを前提にChrome Remote Debuggingを第一候補として提示した。

しかし、最終的な運用環境として想定しているのはVAIO P + Firefox ESRであり、Windows + Chromeの成功事実をそのまま最終方式の前提として扱うのは不適切だと判明した。

## 確定したこと

- Windows + Chromeで認証済みDiMORAページから `GL_FAVPGM_DATA.record[]` を取得できたことは既存の確認事実である。
- Chrome Remote Debuggingは、現時点ではWindows側の技術実証候補であり、本番方式として決定したものではない。
- 最終運用環境の本命はVAIO P + Firefox ESRである。
- Chromeで成立したことからFirefox ESRでも成立すると推測してはいけない。
- Firefox ESRでは、まず `GL_FAVPGM_DATA.record[]` が同様に存在するかを環境差分として確認する必要がある。
- Firefox ESRでデータ構造の存在が確認できた後に、Firefoxをプログラムから安全に操作・取得する方式を比較する。
- Firefox ESRで確認できたことと、VAIO P上で確認できたことも別の状態として記録する。

## 未確定

- Firefox ESR上で `GL_FAVPGM_DATA.record[]` が存在するか。
- Firefox ESRからプログラムで必要データを安全に取得できる具体的方法。
- その方式がVAIO P上で性能・安定性を含めて成立するか。
- 認証状態をプログラムへ渡さず、安全に維持・利用する具体的な構成。

## 今回の判断

当面の次の作業はPython実装やChrome Remote Debuggingの実装ではない。

最初の実証対象を、

> Firefox ESRで認証済みDiMORAページを開いたとき、`GL_FAVPGM_DATA.record[]` が存在し、必要な構造化データを手動で取得できるか

とする。

これを確認後、Firefox ESRからのプログラム取得方式を検討する。

## 失敗・再発防止

- 「現在確認できているWindows + Chromeの事実」に引きずられ、最終運用環境VAIO P + Firefox ESRを最上位条件から外してしまうと、検証環境と本番環境を混同する。
- 「Chromeで取得成功」→「Firefoxでも可能」→「実装開始」という推測の飛躍を行わない。
- 検証環境と最終運用環境が異なる場合は、環境差分を独立した未確認事項として現在化し、確認後に次の実装判断へ進む。
- 過去の成功実績は、別環境での成功を意味しない。

## JUNレビューの位置付け

JUNのレビューは技術的な判断材料であり、自動的に方針を確定するものではない。最終的な方針は、たか＋バドで現在の条件・証拠を確認して決定する。
