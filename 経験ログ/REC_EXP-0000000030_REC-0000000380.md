## 内容
直チャット保存に伴う現在状態の更新を、通常PRで実施したところ、管理用ファイルだけの変更は正規保存トラックで扱う必要があるとしてCIの `Main work progress gate` が失敗した。これを受け、状態更新を保存キュー経由の正規保存ルートへ切り替えた。

保存キューPR #1055 のintake workflowは成功し、正規保存PR #1056を生成した。#1056の必須CIは成功したが、自動承認・マージworkflowでは `Approve as taka2-dev` が `HTTP 401: Bad credentials` で失敗した。原因調査で、GitHub Actions secret `SAVE_APPROVE_TAKA2_TOKEN` に対応するclassic PATが期限切れ（2026-09-25）であることを確認した。

たかが新しいclassic PATを発行し、リポジトリの `SAVE_APPROVE_TAKA2_TOKEN` secretを更新した。その後、失敗ジョブを再実行し、承認・マージが成功したことを確認した。PR #1056は2026-10-13にマージされ、merge commitは `3b7fab5dea1d6e2b97bd0d146b341e319e2eb0aa`。マージ後に `docs/現在状態.json` を読み戻し、状態更新が反映されたことを確認した。

## 確認済み
- 通常PRで管理用状態・生成ビューだけを更新すると、正規保存ルート違反としてCIで拒否された。
- 保存キューPR #1055のintake workflowは成功し、正規保存PR #1056を生成した。
- PR #1056の必須CIは成功した。
- 承認workflowの401エラーは、承認用classic PATの期限切れが原因だった。
- secret更新後の失敗ジョブ再実行で承認・マージが成功した。
- PR #1056はマージ済みで、マージ後の現在状態正本への反映を読み戻し確認した。

## 判断・知見
- 状態・生成ビューのみの更新は、通常の実装PRに混ぜず、定められた正規保存ルートを使用する。
- GitHub Actionsの認証失敗時は、CIの失敗と承認workflowの失敗を区別し、エラーログと対応secretの有効期限を確認する。
- secretを更新して復旧できても、期限切れの再発を自動防止する仕組みが導入されたことにはならない。現在のclassic PATは期限付きであり、恒久的な再発防止策は未解決として扱う。
- 同じ保存要求を未完了だからといって重複投入せず、既存の保存トラックを追跡する。
