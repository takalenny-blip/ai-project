## 1. 背景・課題

`ai-project` の一次記録である `直チャット/` に必要な事実が存在しているにもかかわらず、GitHub検索の結果からは `Chromium`、`chromium`、`launch-light.sh`、`chromium-flags` がヒットしなかった。一方、既知の `048` を直接取得すると、VAIO Pで実行した `~/.config/chromium-flags/launch-light.sh` を確認できた。

この比較により、一次記録の欠如ではなく、GitHub検索経路の到達性・検索indexへの依存が問題であることを実測した。また、`Chromium` と `chromium` の大小文字差を比較しても両方ともヒットしなかったため、大小文字だけでは説明できないことを確認した。

## 2. 今回の判断

索引を先に作って問題を覆うのではなく、**一次記録そのものをGitHub APIから取得し、取得した本文を軽量なPythonで全文検索する経路を作る**方針を採用した。

これにより、GitHubのコード検索indexを一次的な検索手段とせず、リポジトリの一次記録を直接走査できるようにする。

## 3. 実装

` scripts/search_direct_chat.py ` を追加した。

処理は以下の順序とする。

1. GitHub Contents APIで `直チャット/` のファイル一覧を取得する。
2. 各一次記録ファイルの本文をAPIから取得する。
3. Pythonで全文を走査する。
4. ファイル名・行番号・前後の行を結果として出力する。
5. 標準では大文字小文字を無視し、必要に応じて `--case-sensitive` を使用する。

検索対象は一次記録であり、別の索引ファイルを作って検索結果を代替する設計ではない。

## 4. 確認できたこと

GitHub APIによる `直チャット/` の一覧取得が成立し、さらに `048` の本文を直接取得して `~/.config/chromium-flags/launch-light.sh` を確認できた。検索経路の実装ファイルもGitHubへ保存し、読み戻し確認を行った。

実装ファイルの保存コミット：`f3f9d1f1e2835f469a15f61d7e105dee0ee45f7d`

ただし、この段階ではVAIO P等でのスクリプト実行によるエンドツーエンド確認はまだ未完了であり、「完全確立」ではなく「実装済み・API経路成立・実行テスト待ち」と位置付ける。

## 5. 得られた知見

一次記録をGitHubに保存しているだけでは、AIが必要な事実へ迅速に到達できるとは限らない。GitHub検索indexが期待どおり機能しない場合でも、一次記録へ直接到達できるAPI取得経路とローカル全文検索を持っておけば、検索indexに依存しない再現可能な探索手段を確保できる。

また、今回の問題に対しては、索引を追加することよりも先に、一次記録の取得・全文検索そのものを確実にすることが重要である。

## 6. 次の確認

`python3 scripts/search_direct_chat.py chromium` を実行し、`048` と `~/.config/chromium-flags/launch-light.sh` に一発で到達できることを実測する。

これが確認できれば、過去コマンドを確実に拾うための再現可能な検索経路として正式確定する。
