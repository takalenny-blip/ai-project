# REC-0000000180

## 基本情報

- EXP-ID：EXP-0000000030
- REC-ID：REC-0000000180
- 発生日：2026-09-09
- テーマ：EXP→REC→直チャットの網羅調査停止条件を明文化し、少数ファイル停止を防ぐ

## 1. 発生した問題

JUNの過去記録読解が少数ファイルで止まった可能性をきっかけに、`経験ログ → REC → 直チャット` の履歴調査では、通常の「必要な範囲だけ読む」という運用が、AIの主観による少数ファイル停止へつながり得ることを確認した。

READMEは入口・案内であり、調査対象のホワイトリストではない。しかし、この区別が明示されていなければ、AIがREADMEに載ったファイルや最初に選んだ数件だけを読んで調査完了と判断する余地がある。

## 2. 対策

`rules/過去記録調査・追跡フロー.md` を新設し、網羅性が目的の調査では次を必須とした。

1. 対象EXPを確定する。
2. GitHub上の実ファイルから対象EXPのRECを全件列挙する。
3. 各RECの一次記録・関連資料への参照を確認する。
4. 明示的な直チャット参照がないRECは、日付・タイトル・テーマ・本文・ファイル名等から候補を探索する。
5. 候補となった直チャットを確認する。
6. 未特定・未読・除外したものと理由をCoverageとして残す。

「3ファイル読んだ」「READMEに載っているファイルを読んだ」だけでは、網羅調査の完了とはしない。

## 3. 実データによる検証

EXP-0000000030を対象に実際のRECを確認したところ、REC-0000000010～0170の17件を確認した。

ID管理台帳の最終REC-IDだけを見る方法や、CURRENT_STATEに一部記載されたRECだけを見る方法では、過去RECを取りこぼすことを確認した。

また、17件中、REC本文に一次記録への明示参照が確認できたのは3件だった。残り14件については、明示参照がないことを「一次記録が存在しない」と解釈せず、未追跡としてCoverageへ残す設計にした。

この検証により、今回のルールは「少数ファイルを読んだだけで調査完了とする」停止条件を明確に排除できることを確認した。

## 4. 確定した運用

通常のセッション再開では、現在資料・引き継ぎを先に確認し、必要な範囲を段階的に読む。

一方、経緯確認・記事化・漏れ確認・「全部／網羅的に」など網羅性が目的の場合は、通常の読み方へ戻らず、専用の過去記録調査フローへ切り替える。

新規RECを作成する場合は、可能な範囲で関連する `直チャット/` ファイルを一次記録としてREC本文に明示する。

## 5. 未完了事項

EXP-0000000030のRECのうち、一次記録への明示参照がない14件について、直チャット候補そのものをすべて特定・確認したわけではない。

これは今回の運用不具合を防ぐためのルール検証とは別の、過去履歴の追加監査課題として扱う。未追跡のものを追跡済みとは記録しない。
