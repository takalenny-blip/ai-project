# REC-0000000190

## 基本情報

- EXP-ID：`EXP-0000000030`
- REC-ID：`REC-0000000190`
- 発生日：2026-09-10
- テーマ：公開GitHubを一次記録とする運用で、直チャット保存段階から個人情報・秘密情報を保護する方針を確立

## 1. 背景・課題

`ai-project` は公開GitHubを共有・蓄積の中心として運用し、直チャットを一次記録として保存している。これまでにも、パスワード、APIキー、個人情報、仕事の機密情報などを公開情報庫へ入れない必要性は認識されていた。

しかし、直チャットを原文忠実に保存する運用では、保存対象に個人情報・秘密情報が含まれた場合、一次記録としてGitHubへコミットされる時点で公開されるリスクがある。このため、「経験DBへの取り込み時にマスキングする」だけでは遅く、最初の一次記録保存段階で防御する必要があると判断した。

## 2. 今回の判断

直チャット保存の原文固定原則には、安全性を優先する明確な例外を設け、**個人情報・秘密情報を検知した場合は、GitHubへ保存する前に警告し、該当部分を種別ごとのプレースホルダーへマスキングする**方針を正式化した。

このルールはチャット本文だけでなく、画像・スクリーンショット・PDF・Word・Excel・その他添付ファイル、および添付から読み取った情報にも適用する。

作業遂行に必要な情報は会話中の処理に一時的に使用してよいが、GitHubの直チャット一次記録には生の個人情報・秘密情報を保存しない。

## 3. 確立した対策

- 個人情報・秘密情報を検知した場合、保存前に「個人情報・秘密情報が含まれています」と警告する。
- 電話番号、メールアドレス、住所、本名、パスワード、APIキー、認証トークン、カード情報、Cookie、セッション情報等を種別ごとのプレースホルダーへ置換する。
- 画像内に個人情報・秘密情報がある場合も、生の画像を一次記録へ保存せず、保護対象を記録する。
- 通常の番組表、画面状態、操作結果など、秘密ではない情報は必要以上に失わない。
- 「原文忠実保存」と「安全な公開保存」が衝突する場合は、安全性のためのマスキングを優先する。

## 4. 今回の実装・確認

`rules/運用ルール.md` に「### 4-6. 個人情報・秘密情報の保護・マスキング保存」を正式追加した。

今回の変更は、既存の直チャット保存ルールに対する安全上の例外規定であり、直チャット保存段階から適用することを明記した。

関連する直チャット記録 `直チャット/2026-09-10_直チャット即時保存_0033.md` には、今回のルール正式化とGitHub保存・読み戻し確認の事実が記録されている。

## 5. 結果・得られた知見

公開GitHubを一次記録として利用する場合、情報保護は経験DBへの後段処理ではなく、**一次記録の入口で実施する必要がある**ことを確認した。

また、「原文をそのまま残す」という記録精度の原則だけでは、公開情報庫としての安全性を十分に確保できない。原文固定と情報保護を両立させるためには、安全性を優先する明示的な例外規定が必要であることが分かった。

この変更により、直チャット → GitHub → EXP/RECという記録経路の最初の段階で、公開すべきでない情報がそのまま一次記録へ流入することを防ぐ安全弁を確立した。
