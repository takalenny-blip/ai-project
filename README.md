# ai-project

たかとAIが、実際の経験・試行錯誤・判断・気づきを蓄積し、将来の自動化・記事化へつなげるための共有情報庫です。

## AI・バドがこのリポジトリを読む場合

**最初に [rules/運用ルール.md](./rules/運用ルール.md) を読み、共通原則・禁止事項・開始終了・停止条件を確認してください。** 操作別の詳細ルールは、同ファイルの読み込み表に従って必要なものだけを読みます。

日常作業キュー・タスク番号・状態・優先順位・次のアクションの唯一の正本は、Dropboxの固定ファイル `/ChatGPT/Dropbox作業管理統合ボード.xlsx` です。読み取れない場合は停止し、GitHubの古い記述や会話履歴から補完しません。

技術的な事実・仕様は対象のコード・設定・設計資料などの原本で確認します。変更履歴・検証証拠はPR・コミット・GitHub Actions・テスト結果を直接確認します。現在状態を説明するためだけのJSON、ダッシュボード、引き継ぎビューを別の正本として作成・維持しません。

### 起動時・再開時の確認

1. `rules/運用ルール.md` と今回の操作に適用される個別ルールを読む。
2. Dropbox固定ボードから日常作業の状態・優先順位・次のアクションを確認する。
3. 技術的な判断が必要な場合だけ、対象の原本と関連するPR・コミット・Actions・テスト結果を確認する。
4. 過去のチャットや古い資料の「次の一手」を、現在の指示として採用しない。
5. 必要な原本・証拠へ到達できない場合は「未確認」とし、その判断に依存する作業を停止する。

### 画像機能の事前許可（必須）

たか本人の明示的な許可がない限り、画像を表示・検索・生成せず、サムネイル・プレビュー・画像レイアウト・画像コンポーネントも使用しません。

### 送信前ゲート（必須）

回答を送る直前に次を確認します。

1. **画像**：この会話で明示許可を確認できなければ、画像関連の出力・ツール呼び出しを行わない。
2. **依頼範囲**：各段落が直近の指示に直接答えているか。依頼外の説明・提案・予告を削除する。
3. **過去状況**：「現在」「完了済み」「前回」等の主張に、このターンで確認した根拠があるか。なければ未確認とする。
4. **事実区分**：確認済みの事実・提案・未確認を混同しない。

必要な資料を読めない、許可・承認が不明、直近の指示と過去の決定が矛盾する場合は、影響する作業を止めて必要な一点だけ確認します。

## 読解順

1. `rules/運用ルール.md` — 共通原則と操作別ルールの読み込み表
2. Dropbox固定ボード — 日常作業キューの唯一の正本
3. 操作別ルール・対象マニュアル
4. 対象の実装コード・設定・設計資料
5. 関連するPR・コミット・Actions・テスト結果
6. 必要なプロジェクト資料・EXP/REC・直チャット一次記録

`docs/AI_READ_MAP.md` はこの読解順の案内です。`rules/README.md` はルール群の入口です。どちらも運用ルール本文の代わりにはなりません。

## 構造変更時の安全確認

運用ルールの正本・読解順、作業キューの参照経路、保存処理、CIガード、AIが最初に読む入口資料を変更した場合だけ、[構造変更時・独立監査ガード](./rules/構造変更時・独立監査ガード.md)に従って深い監査を行います。日常作業ごとに全体監査を繰り返しません。

## 重要な読み方

- 現在の方針は、過去ログの記述より優先します。
- 過去ログの「次にやること」は現在の命令ではありません。
- 直チャットは原文を一次記録とし、経験DBへの整理は別途行います。
- たかとバドだけで完結できる作業は、それだけで完結して構いません。

## 既存の主な情報領域

- `docs/` — 設計・計画・歴史資料
- `指針等/` — 基準・ID管理等
- `直チャット/` — 実際の会話・作業の原文記録
- `経験ログ/` — EXP / RECとして整理した経験
- `projects/` — 取り組みの資料
- `rules/` — 現在有効な運用ルール

## 秘密情報

公開GitHubにはパスワード、APIキー、アクセストークン、Cookie、その他の認証情報や公開すべきでない個人情報を保存しません。
