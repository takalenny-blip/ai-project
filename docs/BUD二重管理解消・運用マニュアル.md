# BUD.md二重管理解消・運用マニュアル

更新日：2026-10-06

## 1. 目的

現在状態をBUD.mdへ手作業で転記して二重管理する運用をやめ、現在状態の正本を一つにする。

このマニュアルは、現在の仕組みを次回も同じ手順で扱えるようにするための実務手順である。

## 2. 正本と生成物

| 役割 | ファイル | 扱い |
|---|---|---|
| 現在状態の正本 | `docs/現在状態.json` | ここだけを現在状態の判断根拠として更新する |
| 現在ビュー | `BUD.md` | 自動生成。手編集しない |
| 現在ビュー | `docs/引き継ぎ/現在の引き継ぎ.md` | 自動生成。手編集しない |
| 生成処理 | `scripts/generate_current_views.py` | 正本からビューを生成する |
| 整合性ガード | `scripts/current_state_guard.py` | 正本から生成した内容と生成ビューの整合性を検証する |

## 3. 通常の現在状態変更

1. まず `docs/現在状態.json` の現在値を確認する。
2. 変更が必要な項目だけを正本へ反映する。
3. `BUD.md` や `docs/引き継ぎ/現在の引き継ぎ.md` を直接編集しない。
4. GitHub Actionsの生成ビュー同期により、BUD/引き継ぎビューを正本から追随させる。
5. 必要に応じてCIのcurrent-state-guardを確認する。
6. 最後にmain上の `docs/現在状態.json` と生成ビューを読み戻し、正本とビューの関係が成立していることを確認する。

## 4. 保存処理の場合

直チャット保存など、`scripts/save_and_currentize.py` を使う保存経路では、現在状態と生成ビューを保存処理の一括出力として扱う。

保存処理の完了確認は、保存対象そのもの、`docs/現在状態.json`、生成ビューを順に読み戻して確認する。

保存トラックと主作業トラックは分離する。保存処理の結果待ちだけを理由に主作業を停止しない。

## 5. やってはいけないこと

- BUD.mdを現在状態の正本として更新する。
- docs/引き継ぎ/現在の引き継ぎ.mdを現在状態の正本として更新する。
- 正本とビューの両方を手作業で合わせる。
- 古いBUD/引き継ぎの記載だけを根拠に現在状態を判断する。
- 生成ビューの差分を隠すために正本を書き換える。
- 生成ビューの不一致を「見た目が近いから」として未確認のまま完了扱いにする。

## 6. 不一致が出たとき

### 正本とビューが一致しない

1. `docs/現在状態.json` を正本として確認する。
2. `scripts/generate_current_views.py` の生成結果を基準にする。
3. BUD/引き継ぎを手編集して帳尻を合わせない。
4. 生成workflowまたは生成処理の問題なら、その原因を修正する。
5. 修正後、guardとmain上の実体を確認する。

### 生成処理そのものを変更する場合

生成ルールの変更は、BUD/引き継ぎの見た目だけを変更する作業として扱わず、正本から生成される互換ビューの仕様変更として扱う。変更理由、対象、検証結果をPRに残す。

## 7. 次回この作業を行うとき

最初にこのマニュアルと `docs/現在状態.json` を確認する。

既に成功した手順を最初から再発明しない。例外が発生した場合だけ、原因と新しい成功手順をこのマニュアルへ反映する。

## 8. 完了条件

- 現在状態の正本が `docs/現在状態.json` の一つだけである。
- BUD.mdと現在の引き継ぎが手編集されていない。
- 正本から生成ビューを再生成できる。
- guardが生成ビューの整合性を検証できる。
- 次回担当AIがこのマニュアルを読めば、BUD二重管理を再発させずに現在状態を扱える。
