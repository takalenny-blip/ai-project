# セッション引き継ぎ運用

更新日：2026-09-08

## 目的

チャットをリセットしても、次のバドが「前回どこまで確定し、どこから未着手か」を推測せずに再開できるようにする。

## 基本原則

- 引き継ぎは「次回の作業開始点」を残すための現在情報である。
- 過去ログの要約ではなく、次に再開するための作業状態を記録する。
- 確定事項・未確定事項・未着手事項・次の一手を明確に分離する。
- 推測を確定事項として書かない。
- 認証情報、Cookie、session情報、パスワード等は記録しない。
- チャット本文は一次記録。引き継ぎは再開用の索引・状態票として扱う。

## ファイル

`docs/引き継ぎ/現在の引き継ぎ.md` を、現在進行中の作業の再開地点として使用する。

## バドの必須運用

### 作業開始時

1. `BUD.md`
2. `docs/AI_READ_MAP.md`
3. `docs/00_CURRENT_STATE.md`
4. `rules/README.md`
5. `docs/引き継ぎ/現在の引き継ぎ.md`
6. 対象プロジェクトと直チャット/REC

の順で確認する。

### 作業中

重要な確定事項、検証結果、失敗、判断変更が発生したら引き継ぎを更新する。

### チャット終了・リセット前

必ず `docs/引き継ぎ/現在の引き継ぎ.md` を更新し、最低限以下を残す。

- 今回やったこと
- 確定したこと
- まだ確定していないこと
- 未着手のこと
- 次に最初にやる操作
- やってはいけない手戻り
- 関連する直チャット/REC/資料

## 「次に最初にやる操作」のルール

次回のバドは、いきなり操作指示を出さず、まず引き継ぎの「次に最初にやる操作」と現在資料を照合する。

前回すでに試して失敗した操作は、理由が不明でも「再試行禁止候補」として確認してから指示する。

## 状態の書き方

`確定`、`未確定`、`未着手`、`失敗・再試行注意`、`次の一手` の5分類を基本とする。

## DIGA/DiMORAでの適用

DIGA/DiMORAでは、特にブラウザ操作の手戻りを防ぐため、F12、ショートカット、HTML取得方法などの試行結果を記録し、次回に同じ操作を無意味に繰り返さない。

また、`GL_FAVPGM_DATA.record[]` の確認済み事実と、認証済みページをプログラムから取得する未解決課題を混同しない。
