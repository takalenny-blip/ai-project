# セッション引き継ぎ運用

更新日：2026-09-08

## 目的

チャットをリセットしても、次のバドが「前回どこまで確定し、どこから未着手か」を推測せずに再開できるようにする。

## 基本原則

- 引き継ぎは再開時に技術状態・履歴・証拠を参照するための補助資料であり、日常作業キューの正本ではない。
- 日常作業の候補・状態・優先度・次のアクションはDropbox固定ボード `/ChatGPT/Dropbox作業管理統合ボード.xlsx` の記録に従う。過去ログや引き継ぎの「次の一手」から候補を復元しない。
- 確定事項・未確定事項・未着手事項・次の一手を明確に分離する。
- 推測を確定事項として書かない。
- 認証情報、Cookie、session情報、パスワード等は記録しない。
- チャット本文は一次記録。引き継ぎは再開用の索引・状態票として扱う。
- **作業環境の制約（権限、ブラウザ制限、利用不能な機能等）は、次の判断に影響する場合は現在状態として残す。**
- **失敗・再試行注意は、原則として「どの環境で失敗したか」を明記する。ある環境での失敗を、環境条件を確認せずに全環境共通の再試行禁止へ拡張しない。**
- **同一環境で既に失敗した手段は、環境条件が変わらない限り無条件に再試行しない。必要なら別環境で検証する。環境が変わった場合は、同じ手段を改めて検証してよい。**

## ファイル

`docs/現在状態.json` を技術状態・履歴・証拠の正本として参照する。`docs/引き継ぎ/現在の引き継ぎ.md` と `BUD.md` はそこから生成される互換ビューであり、日常作業キューの正本として使わない。日常作業の再開位置はDropbox固定ボードから確認する。

## バドの必須運用

### 作業開始時

1. `docs/現在状態.json` — 技術状態・履歴・証拠を確認する。
2. Dropbox `/ChatGPT/Dropbox作業管理統合ボード.xlsx` — 日常作業の候補・状態・優先度・次のアクションを確認する。
3. `README.md`、`docs/AI_READ_MAP.md`、`rules/運用ルール.md` — 現行の参照先と運用境界を確認する。
4. `BUD.md` と `docs/引き継ぎ/現在の引き継ぎ.md` — 必要な場合だけ生成ビューとして整合を確認する。これらから作業候補を選ばない。
5. 対象プロジェクトと直チャット/REC — 実作業に必要な場合だけ参照する。

の順で確認する。

### 作業中

重要な技術的事実・検証結果・失敗・判断変更・環境制約は `docs/現在状態.json` 等の適切な正本へ反映する。日常作業キューの状態変更はDropbox固定ボードへ反映する。生成ビューを手動編集せず、必要な場合は再生成・一致検証する。

### チャット終了・リセット前

終了時は主作業と保存トラックを分けて完了条件を確認する。技術状態の変更が必要な場合は `docs/現在状態.json` を更新して生成ビューを同期し、日常作業キューの変更が必要な場合はDropbox固定ボードへ反映する。引き継ぎビューを手動で作業キュー化しない。

- 今回やったこと
- 確定したこと
- まだ確定していないこと
- 未着手のこと
- 次に最初にやる操作
- やってはいけない手戻り
- 関連する直チャット/REC/資料
- 必要な場合は、現在の環境制約と別環境へ移す判断

## 「次に最初にやる操作」のルール

次回のバドは、まず `docs/現在状態.json` で技術状態を確認し、Dropbox固定ボードで日常作業の候補・状態・優先度・次のアクションを照合する。引き継ぎや過去ログの「次に最初にやる操作」は、それだけで現行の命令として採用しない。

前回すでに試して失敗した操作は、**失敗した環境と現在の環境が同じかを確認したうえで**再試行可否を判断する。

**環境が変わっていない場合、失敗手段を機械的に繰り返さない。環境が変わっている場合は、同じ手段を再検証することを妨げない。**

## 状態の書き方

`確定`、`未確定`、`未着手`、`失敗・再試行注意`、`次の一手` の5分類を基本とする。

失敗・再試行注意を書く場合は、可能な限り「対象環境」「失敗した操作」「再試行条件」をセットで記録する。

## DIGA/DiMORAでの適用

DIGA/DiMORAでは、特にブラウザ操作の手戻りを防ぐため、F12、ショートカット、HTML取得方法などの試行結果を記録し、**同じ環境で**同じ操作を無意味に繰り返さない。

一方、制限のないPCへ移った場合は、制限付きPCで使えなかったF12、DevTools、HTML確認、ネットワーク確認等を改めて試してよい。環境差を明示したうえで検証結果を引き継ぐ。

また、`GL_FAVPGM_DATA.record[]` の確認済み事実と、認証済みページをプログラムから取得する未解決課題を混同しない。

今回のように、制限付きPCで必要な調査手段が使えない場合は、**そのPCでの調査継続を必須とせず、制限のないPCへ検証を移す判断も正式な作業結果として引き継ぐ。**
