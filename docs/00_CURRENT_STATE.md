JUNレビューでは、Windows + Chromeの取得実績を前提にChrome Remote Debuggingが候補として提示されたが、最終運用環境がVAIO P + Firefox ESRであることを踏まえ、Chrome方式を本番方式として採用しない。まずFirefox ESRで `GL_FAVPGM_DATA.record[]` が存在するかを環境差分として確認する。

### AI作業運用

2026-09-08、過去ログに残った「次にやること」を現在の作業として機械的に再提示してしまう運用上の問題を確認した。

これを受け、過去ログの次作業を現在命令として扱わず、現在資料・引き継ぎ・実績を照合して「現在の次の一手」を再構成する現在化・作業判断ゲートを導入した。

さらに2026-09-09のJUNレビューを受け、同じ種類の再発を注意力だけに依存しないため、以下を正式に運用へ組み込んだ。

- 過去記録を「事実」「過去の判断」「過去の計画」「完了」「失敗／破棄」「再試行条件」「現在有効なルール」「現在の次の一手」に分けて扱う。
- 未完了／完了だけでなく、「当時未完了だが現在は不要」「失敗だが条件変更で再試行可能」「必要だが優先度が低く保留」を区別する。
- **現在の次の一手の基準場所を `docs/00_CURRENT_STATE.md` に限定する。** 引き継ぎの次回操作は再開補助情報としてCURRENT_STATEと整合させる。
- 記録に発生日と必要な環境依存性を残し、環境変更時には過去の成功・失敗・計画の有効性を再評価する。
- 作業開始前に、対象環境・ツールが現在の最上位目標と一致するか、過去のゾンビタスクではないか、過去情報を現在へ持ち込む根拠があるかを確認する。
- 不明確な場合は過去タスクを実行せず、たかへ確認する。

2026-09-09、JUNの直チャット読解が少数ファイルで止まる可能性をきっかけに、**EXP → REC → 直チャットの履歴追跡において、AIが主観で少数ファイルだけ読んで調査完了とする問題**を新たな運用上の不具合として確認した。

この問題は、通常の段階読み込みと、網羅性が目的の履歴調査を同じ「必要な範囲」という言葉で扱えることに起因する。そこで、網羅調査専用の `rules/過去記録調査・追跡フロー.md` を追加し、対象EXPのREC全件列挙、RECごとの一次記録追跡、未特定・未読・除外理由のCoverage確認を必須化した。`README` は入口であり、調査対象のホワイトリストではないことも明文化した。

### 直チャット即時保存

2026-09-09、直チャットの原文性を確保しつつ長大化による一括ファイル更新・読み込み負荷を避けるため、**1ターン1ファイルで即時保存する方式を現在の運用として確定した。**

- ファイル名は `YYYY-MM-DD_直チャット即時保存_連番.md` とする。
- 連番を会話順序の正本とする。
- `[User]` と `[Bud]` の原文を保存し、要約・再構成を原文の代用にしない。
- 保存後はGitHubから読み戻して実在と内容を確認する。
- `直チャット/README.md` は管理方針・索引用の補助資料とし、毎ターン更新しない。
- 通常の再開では全件を毎回読むのではなく、現在資料・引き継ぎを先に確認し、必要な範囲だけ段階的に読む。
- 網羅性が目的の履歴調査では、`rules/過去記録調査・追跡フロー.md` に従って対象集合とCoverageを確認する。

詳細な手順は `rules/AI作業運用フロー.md`、網羅調査手順は `rules/過去記録調査・追跡フロー.md` を参照する。

## 5. 現在有効な記録方針

### 直チャット

テキストを中心に記録する。コマンド、入出力、エラー、設定値、操作結果など、後から事実を再確認できる情報は可能な限りテキストで残す。

正式な原文保存は `直チャット/` の1ターン1ファイル方式で行う。詳細な保存規約は `直チャット/README.md` を参照する。

### 画像

画像は取り組みではなく、**運用ルールとして補助記録に位置づける**。

テキストだけでは十分に表せない実機の外観、物理状態、画面状態等を伝える必要がある場合に使う。重要な事実を画像だけに依存しない。

### 経験DB

直チャットを一次記録として保存し、必要に応じてEXP/RECへ整理する。既存EXPとの関係を確認してから新規EXP・RECを判断する。

今回のDiMORA調査は既存のEXP-0000000010「AIを使った経験・興味・実験の資産化システム構想」に属する経験としてREC化した。

今回のAI作業運用フロー再設計・再発防止の経験は、EXP-0000000030「GitHubを共有情報庫として運用し、経験を蓄積・再利用する経験」にREC-0000000130、0140、0150、0160、0170として記録した。

直チャット即時保存・1ターン1ファイル方式の確定はEXP-0000000040のREC-0000000020に記録した。

今回のEXP→REC→直チャット網羅調査不具合の解消は、既存EXP-0000000030に属する運用経験として今後REC化する。REC化時には、可能な範囲でこの調査に対応する直チャットファイルを一次記録として明示する。

## 9. 現在の次の一手

**今回の現在の次の一手は、EXP → REC → 直チャットの網羅調査ルールが実際に機能することを検証すること。**

まず既存のEXP-0000000030を対象に、実ファイルからREC全件を列挙し、各RECについて一次記録を追跡し、Coverageを作成する。直チャットへの明示リンクがない既存RECについても、日付・テーマ・本文・ファイル名等から候補を探索し、特定できないものは未解決として残す。

この検証で、AIがREADMEに載った少数ファイルだけを読んで調査終了する余地が残っていないかを確認する。必要な追加改修が見つかった場合のみ、現在資料・rules・README等を追加更新する。

この問題の解消後、通常の現在化・作業判断ゲートへ戻り、CURRENT_STATEに記載された技術的な次の一手（VAIO P + Firefox ESRでのDiMORA確認）を改めて再評価する。過去REC・直チャット・旧docsにある次回アクションは自動的に命令として採用しない。

## 10. 運用上の注意

- 認証情報・Cookie・session情報をチャットやGitHubへ露出させない。
- 過去の成功・失敗・計画を現在へ持ち込む場合は、現在の目的・環境・優先度との一致を確認する。
- 現在の必要性が不明な古い未完了タスクを「ゾンビタスク」として実行しない。
- 判断が不明確な場合は、過去タスクを無条件に実行せず、たかへ確認する。
- セッション終了時は、12分類の漏れ防止ゲート、配置チェック、チャット→GitHub差分チェックを行う。
- 直チャットはターン発生時の即時保存を基本とし、保存後のGitHub読み戻し確認までを完了条件とする。
- 網羅調査では、対象集合・Coverage・未解決事項を確認せずに「調査完了」としない。
