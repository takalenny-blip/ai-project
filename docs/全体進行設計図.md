# 全体進行設計図

更新日：2026-09-13

## 目的

この活動を「その場その場の次の操作」ではなく、**全体の到達点 → 大きな工程 → 各工程の完了条件 → 現在地 → 次の一手**で進めるための基準図。

バドは、毎回この図とBUD・運用ルール・現在の引き継ぎを照合してから、たかへ次の一手を指示する。

## 1. 最終到達イメージ

たかの実経験をAIが再利用できる形で蓄積し、そこから実用的な自動化・記事化へつなげる。

大きくは次の順序で進める。

1. **基盤を整える**
2. **実験環境を整える**
3. **自動化対象を一つずつ実証する**
4. **実証済み処理を実用化する**
5. **経験をEXP/RECへ資産化する**
6. **経験から記事素材を抽出・文章化する**
7. **Blogger等へつなげる**

これは大枠の順序であり、各テーマを直線的に一つだけ進める必要はない。ただし、**未確定の前提を飛ばして後工程へ進まない**。

## 2. 現在の作業レーン

### A. VAIO P

目的：低スペックVAIO Pを、必要時に起動して使える補助・実験端末にする。

状態：
- Debian 12 / 32bit / Atom Z520 / RAM 2 GiB。
- システム軽量化は完了。
- Chromium 152.0.7977.75 は `--disable-gpu` で起動可能。
- 日本語入力・スクロール・通常のページ操作を確認済み。
- Chromium起動後のavailableは約1.2 GiB。
- Network Serviceのクラッシュ／再起動メッセージは出たが、ブラウザ実用性は確認済み。

判断：**Chromiumの追加軽量化は現時点では行わない。**

次の作業：VAIO P/Chromiumを目的なく弄り続けず、DiMORA取得検証の実験環境として使う。Chromium自体の追加軽量化へ戻らない。

### B. DiMORA / DIGA自動化

目的：認証済みDiMORAからお気に入り等の情報を安全に取得し、将来の機種別制御・変更検知・警告メール等へつなげる。

状態：
- Windows + Chromeの認証済み環境で `GL_FAVPGM_DATA.record[]` の存在を確認済み。
- 「もっと見る」はページ内record[]の追加表示であることを確認済み。
- 制限付きWindows PCではDevTools操作ができないことを確認済み。
- VAIO P + Firefox ESRでは `GL_FAVPGM_DATA` が見つからず、細かなConsole調査は打ち切り・保留。
- 家PCでの検証を次の作業対象とする方針は廃止。

次の作業：**VAIO P + Chromiumで、認証済みDiMORAページから機械的にデータを取得できる経路を1つ確立する。** `GL_FAVPGM_DATA.record[]` は比較対象とし、同一オブジェクトでなくても等価な機械可読データ取得経路なら可とする。

停止条件：取得方式・認証状態の扱いが確定する前に、本番実装・定期実行・変更検知へ進まない。

### C. 経験DB / 記録基盤

目的：実際の成功・失敗・判断・気づきを、後から再利用できる形で残す。

状態：EXP/RECの仕様・ID管理・直チャット保存ルールは整備済み。直チャットは明示保存時のみ。

次の作業：新しい確定事実・判断・失敗等が発生したら、運用ルールに従ってEXP/REC化を判定する。過去記録の網羅監査は別作業として扱う。

### D. 記事化 / Blogger

目的：蓄積した経験から記事素材を発見し、文章化し、公開につなげる。

状態：最終目的として存在するが、現在の技術検証を飛ばして先に実装しない。

次の作業：自動化・経験蓄積が十分に進んだ段階で、記事化工程を具体化する。

## 3. 各作業の進め方

すべての作業を次の6段階で管理する。

**①目的 → ②完了条件 → ③現状 → ④次の一手 → ⑤実行 → ⑥完了確認・記録**

特に④を空白にしない。たかが「次に何をすればいいのか分からない」状態を作らない。

一つの作業が完了したら、バドが次の作業レーンを選び、必要なら優先順位を更新する。

## 4. 「今はこれ」の決め方

次の優先順位で決める。

1. 重大な未確定前提が残っている作業。
2. 他の工程をブロックしている作業。
3. 短時間で完了条件を判定できる作業。
4. 実用価値が高い作業。
5. 記録・資産化が必要な作業。

ただし、**すでに完了した作業を、別の理由なく再検証し続けない。**

## 5. ループ防止

以下を禁止する。

- 既に確認済みのコマンドを再度やらせる。
- 完了した軽量化を理由なく再開する。
- 同じ失敗条件で同じ調査を繰り返す。
- 「次はどうする？」をたかへ返して判断を丸投げする。
- 過去ログに書かれた古い「次にやること」を現在の命令として扱う。
- 目的・完了条件を示さず、単発コマンドだけを連続して指示する。

## 6. 作業切替のルール

作業レーンを切り替えるときは、バドが次の3点を明示する。

- **今のレーン：** 何をやっているか。
- **完了：** 何が確認できたら一区切りか。
- **次のレーン：** 完了後に何へ進むか。

これにより「今どこにいて、どこへ向かっているのか」を常に追えるようにする。
