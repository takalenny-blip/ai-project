# 全体進行設計図

更新日：2026-09-14

## 目的

この活動を「その場その場の次の操作」ではなく、**全体の到達点 → 大きな工程 → 各工程の完了条件 → 現在地 → 次の一手**で進めるための基準図。

この図はマクロな工程構造を示す。現在の事実・現在の次の一手の正本は `BUD.md`、実際の動き方は `rules/運用ルール.md` とする。

## 1. 最終到達イメージ

たかの実経験をAIが再利用できる形で蓄積し、そこから実用的な自動化・記事化へつなげる。

大きくは次の順序で進める。

1. **基盤を整える**
2. **実験環境を整える**
3. **自動化対象を一つずつ実証する**
4. **実証済み処理を実用化する**
5. **経験をEXP/RECへ資産化する**
6. **経験から記事素材を抽出・文章化する**
7. **Blogger等へつなげる**

これは大枠の順序であり、各テーマを直線的に一つだけ進める必要はない。ただし、**未確定の前提を飛ばして後工程へ進まない**。

## 2. 現在の作業レーンの位置づけ

### A. 基盤・運用

BUD、運用ルール、経験DB、直チャット保存、引き継ぎ等を、AIが現在地を再構成できる基盤として維持する。

### B. 実験環境

VAIO P等の補助・実験環境を、必要な作業に対して再現可能な状態にする。完了した軽量化や基本確認へ理由なく戻らない。

### C. 自動化対象

DiMORA / DIGA等について、取得・制御・変更検知・警告等を一つずつ実証する。現在どこを進めるかはBUDを正本とする。

### D. 資産化・記事化

確定した経験・成功・失敗・判断をEXP/RECへ資産化し、十分な蓄積ができた段階で記事素材化・文章化・公開へ進む。

## 3. 各作業の進め方

すべての作業を次の6段階で管理する。

**①目的 → ②完了条件 → ③現状 → ④次の一手 → ⑤実行 → ⑥完了確認・記録**

特に④を空白にしない。たかが「次に何をすればいいのか分からない」状態を作らない。

一つの作業が完了したら、バドが次の作業レーンを選び、必要なら優先順位を更新する。

## 4. 「今はこれ」の決め方

次の優先順位で決める。

1. 重大な未確定前提が残っている作業。
2. 他の工程をブロックしている作業。
3. 短時間で完了条件を判定できる作業。
4. 実用価値が高い作業。
5. 記録・資産化が必要な作業。

ただし、**すでに完了した作業を、別の理由なく再検証し続けない。**

## 5. ループ防止

以下を禁止する。

- 既に確認済みのコマンドを再度やらせる。
- 完了した軽量化を理由なく再開する。
- 同じ失敗条件で同じ調査を繰り返す。
- 「次はどうする？」をたかへ返して判断を丸投げする。
- 過去ログに書かれた古い「次にやること」を現在の命令として扱う。
- 目的・完了条件を示さず、単発コマンドだけを連続して指示する。

## 6. 作業切替のルール

作業レーンを切り替えるときは、バドが次の3点を明示する。

- **今のレーン：** 何をやっているか。
- **完了：** 何が確認できたら一区切りか。
- **次のレーン：** 完了後に何へ進むか。

これにより「今どこにいて、どこへ向かっているのか」を常に追えるようにする。

## 7. 現時点の全体地図

```text
全体目的
  ↓
経験を蓄積 → AIで再利用 → 自動化・記事化
  ↓
┌─────────────────────────────┐
│ 基盤：BUD / 運用ルール / EXP / REC / 引き継ぎ │
└─────────────────────────────┘
          ↓
     実験・検証環境
       ↓
    自動化対象の実証
       ↓
      自動化へ
       ↓
  変更検知・機種別制御
       ↓
    警告メール等
       ↓
    経験DBへ資産化
       ↓
     記事化・Blogger
```

現在の具体的な作業対象・完了条件・次の一手は、ここでは固定せず `BUD.md` に集約する。

## 8. 更新ルール

この設計図は大枠の工程構造を維持し、工程そのもの・完了条件の考え方・大きな方針が変わったときだけ更新する。

現在地・現在の次の一手・技術的な細部をこのファイルへ重複記録しない。現在の事実が変わった場合はまずBUDを更新する。

直チャット保存は別途 `rules/運用ルール.md` に従う。
