# AI_READ_MAP — AI / バドの読解マップ

更新日：2026-09-14

## 1. 位置づけ

**現在の意味上の最上位資料は `BUD.md`。**

BUDに現在の目的・現在状態・現在の次の一手を集約する。作業手順・運用ルールは `rules/運用ルール.md` に一本化している。

`docs/全体進行設計図.md` は、現在状態の正本ではなく、全体の到達点と大きな工程を把握するためのマクロ設計図である。

このファイル自体は現在情報の正本を持たない。

## 2. 新しいセッションの必須起動ゲート

**BUD・運用ルール・全体進行設計図・現在の引き継ぎを確認するまで、作業を開始しない。**

読解順は次のとおり。

1. `BUD.md` — 現在の目的・現在状態・現在の次の一手
2. `rules/運用ルール.md` — 現在の作業手順・横断的な運用ルール
3. `docs/全体進行設計図.md` — 全体の到達点・大きな工程・作業レーン
4. `docs/引き継ぎ/現在の引き継ぎ.md` — 直前セッションの再開情報
5. `projects/` — 関係するプロジェクト資料
6. 必要なEXP / REC / `直チャット/`
7. 過去資料 — 経緯・出所・歴史を調べる必要がある場合のみ

`rules/README.md` はルール入口、`docs/AI_READ_MAP.md` はこの読解案内であり、どちらもBUDの代わりに現在状態を定義しない。

## 3. 情報の優先順位

**BUD.md（現在状態） + rules/運用ルール.md（行動規則） > 全体進行設計図（マクロ構造） > 現在の引き継ぎ（前回スナップショット） > 過去資料・過去ログ**

現在の次の一手はBUDを正本とする。全体進行設計図と引き継ぎに古い記述が残っていても、過去ログから現在命令を推定しない。

過去資料は歴史として保持する。現在資料と過去資料が食い違う場合は、勝手に混ぜず、現在の事実・過去の事実・未確定事項・過去の計画等を区別する。

## 4. 横断的な会話制御

`rules/運用ルール.md` の横断ゲートを会話・作業制御の基準として読む。

- 強いネガティブ評価・意思疎通異常は、作業停止／インタビューのトリガーである。
- インタビューは「作業停止時だけ」ではない。作業中でも評価・判断・実感を取りこぼしそうなら起動する。
- ポジティブな価値発見（「これはよかった」「使える」「面白い」「うまくいった」等）も、再利用価値が曖昧なら短いインタビューを行う。
- JUN等の外部提案は「把握 → 理解 → 採否判断 → 案作成 → たかへ提案 → 実行 → 検証」で扱う。
- ルール追加は文章量の増加ではなく、トリガー・必須行動・完了条件・検証例まで定義されて初めて有効とみなす。

## 5. 通常読解と履歴調査の切り分け

通常時は、必須起動ゲートを通った後、必要な範囲だけ段階的に読む。

一方、「漏れなく」「全部」「網羅的に」、経緯確認、記事化、出所確認など**網羅性が目的の調査**では、AIの主観で数件を選んで終了してはいけない。

その場合は `rules/運用ルール.md` の「運用フロー（過去記録調査）」を適用し、対象EXP → REC全件列挙 → 一次記録追跡 → Coverage確認まで行う。

## 6. たか・バド・その他AI

- **たか**：活動の中心。実際に経験し、試し、使い、判断し、最終的に決める。
- **バド**：たかと協働するAI。必要に応じて検索・整理、設計、分析、提案、文章化、実装、検証、経験資産化を担う。
- **JUN / Claude / その他**：必要なときに使う補助手段。固定役割・必須工程ではない。

## 7. 記録と現在状態

- 直チャットは一次記録。正式保存は現在、たかが明示したときだけ行う。
- ユーザーが貼ったJUN・Claude等の回答も、提示された原文を省略・要約・再構成せず保存する。
- EXP/RECは経験を整理した記録。IDは `指針等/ID管理台帳.md` を基準とする。
- 画像は補助記録であり、重要な事実を画像だけに依存しない。
- 重要な現在認識はBUDへ反映し、過去資料を現在の事実へ書き換えない。

## 8. 引き継ぎ

`docs/引き継ぎ/現在の引き継ぎ.md` は直前セッションの再開情報を保持する**スナップショット**であり、独立した現在状態の正本ではない。

現在の目的・現在状態・次の一手はBUDを基準とする。引き継ぎの記述はBUDと整合させ、古くなった場合はBUDを優先して更新する。

環境制約、失敗、未確定、やってはいけない手戻りも、次の判断に影響する場合は引き継ぐ。
