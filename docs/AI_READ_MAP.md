# AI_READ_MAP — AI / バドの読解マップ

更新日: 2026-09-08

## 1. 目的

このファイルは、初めて `ai-project` を読むAIが、過去資料を読み違えて現在の方針を誤認しないためのナビゲーションマップです。

**意味上の最上位コンテキストは `BUD.md`、読解順を示す地図はこの `AI_READ_MAP.md` です。**

## 2. 最初に読む順番

1. `BUD.md`
2. `docs/AI_READ_MAP.md`
3. `docs/00_CURRENT_STATE.md`
4. `rules/README.md` と、必要な現在ルール
5. `docs/引き継ぎ/現在の引き継ぎ.md` — 直前セッションの再開地点
6. `projects/README.md` と、関係するプロジェクト資料
7. 必要な経験ログ・REC
8. 必要な `直チャット/` — 一次記録。必要なときは原文まで戻る
9. `docs/`・`指針等/` にある旧資料 — 現在との整合を確認しながら履歴として参照

**新しいセッションでは、現在資料と引き継ぎを確認するまで、操作指示や実装方針を確定しない。**

## 3. 情報の優先順位

現在の判断では、原則として次の順で扱います。

**BUD.md / CURRENT_STATE / 現在のrules・projects / 現在の引き継ぎ > 過去の資料・過去ログ**

ただし、過去ログは「なかったこと」にしません。過去に何が起きたかを知るための一次資料として保持します。

現在資料と過去資料が食い違う場合は、勝手に混ぜず、次のどれかとして扱います。

- 現在のルール
- 過去の事実
- 現在も確認が必要な事項
- 未決定事項

引き継ぎとCURRENT_STATE等が食い違う場合も、勝手に統合せず、**直前セッションで発生した変更なのか、引き継ぎの更新漏れなのかを確認する。**

重要な変更は、たかの判断を確認したうえで現在資料へ反映します。

## 4. たか・バド・その他AIの現在認識

- **たか**: この活動の中心。実際に経験し、試し、使い、判断し、最終的に決める。
- **バド**: たかと一緒に進めるAI。過去経験の検索・整理、設計、分析、提案、文章化、実装、検証、経験資産化などを必要に応じて担当できる。
- **JUN / Claude / その他のAI・ツール**: 必要なときに使う補助手段。固定された工程や担当ではない。

したがって、**たか＋バドだけで完結するなら、それで完結してよい。**

過去資料に「Claudeがコード担当」「JUNが現場担当」などの記述があっても、それは当時の作業方法・履歴として読む。現在の固定役割とは解釈しない。

## 5. プロジェクトとルールを混同しない

### プロジェクト / 取り組み

実際に進める対象・目的・作業・成果物を持つもの。

現在特に重要なのは、

- VAIO Pを自動化の実運用基盤として整備すること
- DIGA自動化。特に「お気に入り・機種別制御・警告メール」をVAIO P上で今後さらに自動化すること
- 経験DBを育てること

### ルール

作業の進め方・記録方法・判断方法など、複数の活動に横断して適用されるもの。

**「セッション引き継ぎを残す」ことは個別プロジェクトではなく、全プロジェクトに適用する運用ルールです。**

### 履歴 / provenance

「Claudeを使った」「JUNと作業した」などは、その作業がどう行われたかを示す履歴情報です。現在の役割分担を意味しません。

## 6. DIGAについて

DIGAの過去ログには、録画管理・お気に入り管理・機種別制御・警告メールなどの具体的な試行や設計検討があります。

これらは単なる「Claudeが作ったスクリプト」の記録としてではなく、今後VAIO Pで自動化を進めるために再利用できる経験・設計知識として扱います。

## 7. 経験DB・一次記録

- 直チャットは一次記録として重要。
- 正式登録した直チャットは、原文を基本として保存する。
- 必要に応じてEXP / RECへ整理する。
- 事実と推測を混ぜない。
- 過去RECを都合よく書き換えず、訂正や追加は新しい記録として扱う。
- IDルールは `指針等/ID管理台帳.md` と確定版の経験DB運用仕様を参照する。

## 8. セッション引き継ぎ

`docs/引き継ぎ/README.md` が引き継ぎ運用の詳細を定義し、`docs/引き継ぎ/現在の引き継ぎ.md` が直近の再開地点を保持します。

引き継ぎには最低限、以下を残します。

- 今回やったこと
- 確定したこと
- 未確定のこと
- 未着手のこと
- 失敗・再試行注意
- 次に最初にやる操作
- やってはいけない手戻り
- 関連資料

「何をしたか」だけでなく、**何をしなかったか、何が失敗したか、次に何をしないべきか**を残すことを重視します。

## 9. 読み方の基本姿勢

AIは、過去資料から現在のルールを推測してはいけません。

まず現在資料と引き継ぎを読み、その後に必要な過去ログを調べます。過去ログを読む目的は、現在の判断材料になる実経験・経緯・失敗・成功・設計知識を回収することです。

このリポジトリの目的は、隠れたAIの記憶に依存せず、**新しいバドでもGitHubを読めば、たかとこれまで積み上げてきた文脈を再構成できる状態**を作ることです。
