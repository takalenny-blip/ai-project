## Debianを入れて、VAIO Pを動かしていく

VAIO Pを実際に動かしてみる。

使っているのはVGN-P70H/W。Atom Z520の32bit機なので、Debianもi386版を選ぶことになった。

ここからは、母艦PCでDebianのインストールメディアを作り、VAIO Pに入れていく。

このとき、JUNから「写真で残したら？」というアドバイスもあった。

そこで、たかもこう返している。

「写真で残したら？のアドバイスもよろしく！母艦PCはある。debianのダウンロードからだね。ここから一緒にやろうぜ！」

ただ、単に写真を撮るだけではなく、あとからこの経験そのものを記事にできないか、ということも考えていた。

まずはDebianをダウンロードする。

「今、debianダウンロード中」

ダウンロードしたのは、Debian 12.12.0のi386版netinst。

次にRufusを使ってUSBメモリに書き込む。

画面を見ながら進めていると、AIが一度、Windowsの通常フォーマット画面だと勘違いした。

「ん？rufasだよ」

AIもすぐに勘違いを認めた。

Rufusの画面には、ボリュームラベルとして「Debian 12.12.0 i386 n」と表示されていた。

USBメディアができた。

いよいよVAIO Pを起動する。

ところが、ここで最初のトラブル。

「何だろ？電源入らん」

電源が入らない。

充電ランプを見ると赤点滅している。

古いVAIOなので、バッテリーの状態も怪しい。

そこで、バッテリーを外してACアダプターだけで起動してみることになった。

「バッテリー外したら起動。」

さっきまで電源が入らなかったVAIO Pが起動した。

しかも、USBからDebianのインストーラーまで立ち上がった。

いきなり「古いPCだから壊れているのか？」と思わせられたが、実際にはバッテリーを外すことで先へ進めた。

ここからDebianのインストールが始まる。

言語やキーボード、ネットワークなどを画面に従って設定していく。

途中、VAIO Pの無線LANも認識されていた。

インストール先のストレージについては、以前のSSD換装の話があったため、ここでも確認が必要だった。

実際には、SSD換装は見送っている。

今回は元のHDDにDebianを入れる。

ところが、ここでAI側に記憶違いが起きた。

JUNが、VAIO PにはKingdataの64GB SSDが入っているという前提で話し始めた。

そこで、たかが訂正する。

「換装は見送り、HDDにインストールする方針にしたんだぜ？SSDは外付けで活用しようかって話したじゃん」

この場面は、単なるインストール手順では終わらなかった。

AIと一緒に作業していると、以前の会話を正確に引き継げているとは限らない。

だから、実際の作業現場にいる人間が「今どうなっているか」を確認しながら進める必要がある。

今回は、その訂正を入れて、元のHDDへのインストールを続けた。

「今はベースシステムのインストール中」

あとは待つしかない。

HDDなので、とにかく時間がかかる。

「ソフトウェアの選択とインストール、5%」

少しずつ数字が進む。

「今はソフトウェアの選択とインストール50%」

途中で、インストールそのものだけでなく、この先の最終ゴールについても気になってきた。

「それってインストールでしょ？そうじゃなくて、最終ゴールまでの。」

Debianを入れること自体が目的ではない。

VAIO Pをサーバーとして使い、その先でブログや自動化につなげたい。

そのための最初の一歩が、今やっているDebianのインストールだった。

インストールはさらに進む。

57%。

94%。

そしてGRUBの設定。

「インストールを終了しています」が25%まで進んだところで、ようやく終わりが見えてきた。

長かった。

そして、ついにインストール完了。

再起動する。

ここまで来ても、本当にHDDからDebianが起動するのかはまだ分からない。

そして、

「うまく起動したぜ！」

VAIO Pが起動した。

デスクトップにはLXDEが表示された。

「LXDEシンプルでいいな！」

古いVAIO Pに、DebianとLXDEが動いている。

まずは成功だ。

ただし、ここで終わりではなかった。

次に確認したかったのはネットワーク。

ところが、Wi-Fiが使えない。

「Wi-Fiない？」

無線LANが見えない。

ここからは、画面を見ながらコマンドを一つずつ試していく。

まず、ネットワークインターフェースを確認する。

```bash
rfkill list
```

続いて、

```bash
ip link
```

ネットワーク管理にはNetworkManagerを使うことにして、

```bash
sudo nmtui
```

を起動する。

しかし、Wi-Fiが出てこない。

「見えねー」

そこで、NetworkManagerの状態を確認する。

```bash
nmcli device
```

すると、無線LANインターフェース `wlp2s0` が「unmanaged」、つまり「管理なし」になっていた。

たか：

「管理なし」

ここから原因を切り分ける。

まずNetworkManagerに管理させてみる。

```bash
sudo nmcli device set wlp2s0 managed yes
```

それでも変わらない。

そこで、設定ファイルを確認する。

```bash
cat /etc/network/interfaces
```

すると、`wlp2s0` に関する設定が残っていることが分かった。

NetworkManagerと、以前のネットワーク設定がぶつかっているらしい。

そこで、無線LAN関連の設定をコメントアウトする。

```bash
sudo sed -i '/wlp2s0/s/^/#/' /etc/network/interfaces

sudo sed -i '/wpa-ssid/s/^/#/' /etc/network/interfaces

sudo sed -i '/wpa-psk/s/^/#/' /etc/network/interfaces
```

続いてNetworkManagerを再起動。

```bash
sudo systemctl restart NetworkManager
```

そして、もう一度確認する。

```bash
nmcli device
```

今度は `wlp2s0` が「管理なし」ではなく、「切断済み」に変わった。

少なくとも、NetworkManagerが無線LANを管理できる状態になった。

そして、

```bash
sudo nmtui
```

を起動する。

今度はWi-FiのSSIDが表示された。

「出たーーー」

ここからWi-Fiを選択して接続。

接続後、iPhoneのUSBテザリングを外して、Wi-Fiだけで本当にインターネットにつながっているか確認する。

```bash
ping -c 3 8.8.8.8
```

そして、

「繋がった。画面はとじていいの？」

画面を閉じて、最終確認。

「オケ」

Wi-Fiも復旧した。

ここまで来ると、VAIO Pが少しずつ「使える機械」になってきた感じがする。

ただ、実際に使ってみると、また問題が出た。

Firefoxを起動する。

「firefoxは変わらず重い。。。」

Debianは起動した。

LXDEも動いた。

Wi-Fiもつながった。

でも、Firefoxは重い。

そこで次は、軽量なブラウザを探すことになった。

こうしてVAIO Pは、

**電源が入らない → バッテリーを外す → Debianを入れる → Wi-Fiが見えない → コマンドで原因を切り分ける → NetworkManagerで復旧 → Firefoxが重い**

という具合に、一つ問題を解決すると、また次の問題が出てくる状態になった。

それでも、最初の「VAIO Pをサーバーにしてみたい」というところから考えれば、かなり前に進んでいる。

そして、この一連の作業をAIとの会話と一緒に記録していくこと自体が、あとになって重要な意味を持つことになる。
