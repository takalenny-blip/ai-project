# BLOG-0001 企画案 v1

## 仮タイトル
「便利そう」から始まった。AIと一緒に、自分の経験を掘り始めるまで

## 企画の核
2026/9/1、Claudeのブラウザ連携についてのニュースを見て「便利そうだな」と思ったことが出発点だった。そこからGemini、Python、手動DIGA情報チェック、24時間待ち受け、以前作ったVAIO P Linuxサーバー、ブログ再開、ChatGPTへとつながり、9/5前後には「経験を生みながら、経験を扱う仕組みも同時に育てている」という気づきに至った。

最初からAIブログ自動化を計画していた話にはしない。小さな興味が、試行と過去資産の再利用とAIとの会話によって、思いがけず「自分の経験を掘る」活動へ広がった過程を描く。

## 時系列と本文で見せる場面

### 1. 2026/9/1――「便利そうだな」
Claudeのブラウザ連携をネットニュースで見た。ここを物語の原点にする。技術解説ではなく、最初の小さな反応を置く。

### 2. Gemini、そしてPython
「ジェミニでも同じようなことできないかな？」と聞き、Pythonで何かできそうだと考えた。「ニュースを見た」から「自分で試す」への変化。

### 3. PythonがDIGAにつながる
当時手動でやっていたDIGA情報チェックへ適用できそうだと考えた。DIGAそのものを主役にせず、技術の可能性が自分の現実の作業へ接続された場面として描く。

### 4. 24時間待ち受けとVAIO P
24時間の待ち受けサーバーが必要になり、以前プロキシ＋逆プロキシで立てたVAIO PのLinuxサーバーを思い出した。「昔作ったもの」が「今の試行」に再利用できる場面。

### 5. 「他に用途ないかな」→「またブログやりたい」
サーバーの用途を考えていると、以前から思っていた「またブログやりたいなー」が浮かぶ。ブログは最初から今回の目的だったのではなく、別の試行から思い出された。

### 6. ChatGPTに「力を見ようと思って」聞く
「その作成をAIと一緒にできないかな」と考え、使い始めたChatGPTに相談した。ここはAI導入の説明より、本人の動機「力を見ようと思って」を中心に置く。

### 7. ブログ自動化から、経験を扱う方向へ
9/1〜5のやりとりで、ブログ自動化だけでなくAI・経験・経験を扱う仕組みへ関心が広がった。後付けで最初から設計していたことにはしない。

### 8. 経験DBそのものが経験になる
一次記録には「EXP-0000000020で『経験』を生み、EXP-0000000030で『経験を扱う仕組み』を同時に育てている」とあり、「今日の出来事によって、この経験DBそのものについて何が分かった？」という観察軸も生まれている。ここを企画の着地点にする。

## 中心線
**小さな「便利そう」が、試行・再利用・AIとの会話を通じて、最初には想定していなかった「自分の経験を掘る」活動へ変わっていった。**

A「小さな便利そう」は入口、B「AIとの会話から次の仕事・発想が生まれる」は展開、C「経験を扱う仕組み自体が経験になる」は到達点。3つを別テーマとして並べず、一本の時間軸として描く。

## 読者に渡すもの
AIで何を自動化できたかだけではなく、目的を最初から完成させていなくても、試すことで次の用途や次の問いが生まれる過程を見せる。

試す → 別の用途につながる → 過去の資産を思い出す → やりたかったことを思い出す → AIに相談する → 相談そのものから次のテーマが生まれる、という流れが読者に残る形を目指す。

## 書き方の原則
- 時系列を崩さない。
- 9/1を明確な起点にする。
- DIGAやVAIO Pを技術記事化しすぎない。
- 「最初からブログ自動化を計画していた」と後付けしない。
- 実際に起きたことと、後から見た意味を分ける。
- ChatGPTの能力を宣伝する記事にはしない。
- 自動化の成果だけで終わらせない。
- 経験DBの気づきを到達点として扱う。

## 残確認
9/1〜5の一次記録からScene 7で使う具体的な会話・転換だけを必要最小限確認する。Scene 1〜6は既に確認済みの本人発言を骨格として扱う。タイトル、冒頭の文章、長さは本文段階で決める。

## 企画段階の完了条件
1. 9/1から9/5前後までの時系列が固定される。
2. 各転換点の因果が説明できる。
3. 中心線が一文で言える。
4. 事実と後付けの解釈を区別できる。
5. 追加確認する一次記録が限定される。
6. たかが中心線を確認した後、本文作成へ進める。
