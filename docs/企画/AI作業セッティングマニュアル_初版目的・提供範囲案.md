# AI作業のセッティングマニュアル：初版の目的・提供範囲案

## 1. 起点となる欲求と対象読者

本マニュアルは、すでに問題を抱えている読者だけを対象に、その問題を解決するためのものではない。起点は「AIで何かを実現したい」「いろいろ試したい」「AIでできることを広げたい」という欲求である。

決定済みの対象読者は次のとおり。絞り直さない。

- AIでいろいろ試したい人
- AIとの作業で得た経験を蓄積し、できれば公開したい人
- 「AIを使って何かできないかな？」と考えている人
- 生成AIの利用から仕組み作り、公開まで、無料でできることを大前提とする。

読者が実現したいことを出発点に、必要な準備・知識・手順をマニュアル群として順々に提供する。作業上の困りごとは、実現の過程で必要になったときに扱い、最初から唯一の中心課題として仮定しない。

## 2. マニュアル群の中での初版の役割

マニュアル群は、設定・準備、実際の運用、成果の整理・公開へと段階的に提供する構想である。本書が扱うのはそのうち**最初の「AI作業のセッティングマニュアル」1冊**であり、3冊すべての内容を初版に詰め込まない。

初版の役割は、読者がAIを使った小さな取り組みを実際に始め、試行錯誤の結果を残し、次の作業や再利用できる知識につなげるための準備を整えること。後続マニュアルで扱う本格的な運用方法や、成果を公開する工程全体を本書だけで完結させることは目指さない。

## 3. 初版に含める範囲案

既存の7章構成を土台に、次の内容を初版の範囲とする案。

1. **目的と全体像**：自分がAIで試したいこと・実現したいことを一つ選び、AI、チャット記録、GitHub、Dropboxの役割と保存先を整理する。
2. **AIの利用環境と基本ルール**：AIの役割、目的、作業範囲、完了条件、承認が必要な操作を伝える開始テンプレートを用意する。事実・提案・未確認事項を区別する。
3. **GitHubの基本設定と記録管理**：リポジトリ、ファイル、コミット、ブランチ、Pull Requestの基本を知り、Markdownの正本と生成ビューを区別する。
4. **ChatGPTチャットをMarkdownで保存するブラウザー拡張機能の選択肢**：候補の提供元、更新状況、権限、プライバシー、データの扱いを確認し、テストチャットで日本語・見出し・コード・リンク等の出力を確認する。候補を安全性未確認のまま推奨・断定しない。
5. **Dropboxの設定とファイル管理**：原本、作業ファイル、公開用成果物などの保管場所を整理し、Dropbox上のファイルとGitHubの正本を混同しない。
6. **ツールの役割分担と連携**：小さな模擬作業を通して、AIとの対話、Markdown記録、GitHubでの管理、Dropboxでの保管をつなぐ。
7. **設定完了テスト**：小さな作業を実施し、結果・確認済み事項・未完了事項を記録し、記録から後で作業を再開できるかを確かめる。

拡張機能は初版で扱う選択肢に含める。ただし、特定の拡張機能を必須ツールとして固定することと、選定・検証の方法を説明することは分ける。安全性や権限を確認できない場合は、導入を保留する選択肢も示す。

## 4. 初版では必須にしない範囲案

- 自動化スクリプトや複雑なCIの構築
- 有料サービスの利用を前提とする手順
- 特定のブラウザー拡張機能を、比較・安全性確認前に必須指定すること
- Word（.docx）版の作成
- 装飾目的の図・イラスト
- 後続の運用マニュアル・公開マニュアル全体の内容
- Noteでの販売準備、価格決定、販売開始

これらを永久に対象外とする決定ではない。初版の役割と既決の制作仕様に照らし、初版の必須範囲に入れないという案である。

## 5. 初版の完成条件案（マニュアル成果物そのもの）

完成条件は、公開後の運用や需要検証ではなく、**初版マニュアルの内容と、読者がそれを使って達成できること**に限定する。

- 既決の対象読者と「AIで何かを実現したい」という出発点に沿っている。
- 読者がAIで試したい小さな取り組みを選び、必要な環境・ルールを準備する手順がある。
- 開始テンプレート、記録テンプレート、確認チェックリストなど、必要な成果物が実際に使える形で含まれる。
- AI、Markdown、GitHub、Dropboxの役割と、正本・保管場所の区別が説明されている。
- ChatGPTチャットのMarkdown保存拡張機能について、選択時の確認事項とテスト方法が含まれている。
- 説明した手順を実行し、結果・確認済み事項・未完了事項を記録できる。
- 各手順の前提条件、期待結果、確認方法、失敗時の確認が明記されている。
- 確認済みの事実、仮説、未検証事項、制約を区別し、未検証の内容を確定事実として記述していない。
- 想定読者が一連の手順を実際に通せるか、実地検証の対象と判定方法が定義されている。

## 6. 完成条件に含めない後続工程

以下は重要だが、初版マニュアルそのものの完成条件には含めない。マニュアル群の統合管理設計と現在状態の作業キューで、独立した後続工程として管理する。

- GitHub Pagesへの公開反映と公開ページの実表示確認
- 公開後のアクセス・反応・利用者フィードバックの観測
- Note等を用いた需要・購入意向の検証
- 販売・価格・正式仕様・開始時期の判断
- 公開後の保守・改訂

## 7. 決定状態

この文書は範囲を確認するための案であり、承認済みの仕様ではない。対象読者や無料前提を再検討するものでもない。たかの確認後に、必要な修正を反映して初版範囲を確定する。確定前に本文制作へ進んだことをもって、案が承認されたとみなさない。
