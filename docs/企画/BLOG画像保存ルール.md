# ブログ画像の保存ルール

## フォルダー構成の変更承認（必須）

- 新しいフォルダーの作成、既存フォルダーの削除・移動・改名、保存場所の構成変更は、実行前にたかの明示承認を得る。承認がない限り実行しない。
- 既存フォルダーに置けばよいか判断できない場合も、勝手に新設せず、候補パスと理由を提示して確認する。
- ファイルの追加・移動でも、既存ルールや指示から保存先が一意に決まらない場合は事前確認する。
- 作業前に既存のフォルダー構成と参照元を調べ、変更範囲・影響・削除対象を提示する。承認後に変更し、参照・ビルド・テストを検証する。
- 不要なフォルダーやファイルを作ってしまった場合は、残置を正当化せず、依存参照を移行・検証してから削除する。削除できていない場合は未完了と明記する。

## 標準保存先

- 記事専用の画像は、記事IDに対応する既存フォルダー `docs/企画/BLOG-NNNN/images/` に保存する。
- ファイル名は記事IDを含め、例：`blog-0004-four-panel.png` のように用途が分かる名前にする。
- Blogger掲載用HTMLは、同じ記事フォルダーに保存した画像をGitHubのraw URLで参照する。
- 記事専用画像は記事ごとの既存 `images/` フォルダーに保存する。サイト全体で共用する素材（例：サイトバナー）は既存の `docs/assets/` に保存し、生成物の置き場と素材の保存先を混同しない。
- 既存の画像フォルダーや保存ルールを確認してから作業し、記事ごとの新規フォルダーをむやみに増やさない。標準フォルダーが既にあれば再利用する。

## 変更時の確認

1. HTML内の画像URLが標準保存先を指していること。
2. 画像ファイルがGitHub上の指定パスに存在すること。
3. ビルド・回帰テストの画像URL期待値を更新すること。
4. 公開ページで画像表示を確認すること。確認できていない場合は「未確認」と記録する。
