# AI作業のセッティングマニュアル：制作形式・文体仕様

- 状態：**決定済み**
- 決定日：2026-10-13
- 適用対象：先行する「AI作業のセッティングマニュアル」。
- 方針の前提：[決定済み対象読者・基本方針](AI作業セッティングマニュアル_決定済み対象読者.md) を維持し、対象読者や無料前提を再検討しない。

## 1. 原稿の正本と公開形式

1. **原稿の正本はMarkdown（`.md`）**とし、GitHubリポジトリで版管理する。
2. **GitHub Pagesを無料公開の本拠地**とする。原稿の保存、公開環境への反映、実際の表示確認は別の状態として管理する。
3. Note向けの内容を用意する場合は、Markdownの正本から掲載先に合わせて文章を調整する。初期段階では同じ本文を複数形式で二重管理しない。
4. **Word（`.docx`）ファイルは初版では作成しない。** 読者が保存・編集・印刷する必要性など、具体的な需要が確認できた時点で改めて判断する。
5. Noteは需要検証の候補経路であり、有料販売や販売開始を既定路線としない。

## 2. 書きぶりと構成

- 読者が実際に作業しながら参照できる、**文章・具体例・手順・コマンド中心の実用マニュアル**とする。
- 手順は番号付きで、実施順が分かるように書く。
- 必要に応じて、各作業単位に「目的」「事前条件」「手順」「期待する結果」「確認方法」「うまくいかない場合」を記載する。
- コマンド、設定例、テンプレートはコピーしやすいコードブロック等で示し、変更が必要な箇所や実行前の注意を明記する。
- 専門用語や前提知識を当然視せず、初めて試す読者にも次の操作が分かる説明にする。
- 適用条件、制約、失敗時の対処、未解決事項も記載する。効果を誇張したり、未検証の内容を検証済みとして書いたりしない。

## 3. 図・画像・装飾

1. **図・イラストは原則として使用しない。** 文章と手順で理解・実行できることを優先する。
2. 図や画像は、文章だけでは関係性や操作対象が伝わりにくく、理解や実行を明確に改善すると判断できる箇所に限って追加を検討する。
3. 画面例が必要な場合も、実際の画面や状態に基づくものを使用し、架空の画面や実在しない操作を作らない。
4. 見栄えのためだけの図・イラスト・装飾を追加しない。

## 4. 制作・公開時の確認

- [ ] Markdown原稿が正本として管理されている
- [ ] 手順・コマンド・テンプレートが読者にとって具体的で実行可能
- [ ] 検証済み、未検証、仮説、制約が区別されている
- [ ] 図や画像は必要性がある場合にのみ含まれている
- [ ] GitHub Pagesでの無料公開と実表示確認を別々に記録している
- [ ] Word形式や有料販売を、需要確認・明示的判断なしに追加していない

**変更管理：** この仕様は2026-10-13に承認された決定事項である。チャットや担当AIの切替、制作工程の進行を理由に再検討へ戻さない。変更が必要な場合は、理由と影響を示してたかの明示的承認を得てから正本と関連資料を同期する。
