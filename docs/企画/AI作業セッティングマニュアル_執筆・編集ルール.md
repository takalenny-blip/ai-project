# AI作業セッティングマニュアル 執筆・編集ルール

状態：執筆方針として合意済み。各ツールの仕様・操作手順は掲載前に個別確認する。

## 1. 目的と到達点
- 読者が無料で始められる環境を整え、実際に試し、結果を保存・再確認できるところまで案内する。
- セッティングと運用を機械的に分けず、準備する意義と準備した環境の使い方を一続きで説明する。
- 読者に選択を丸投げせず、候補・比較・採用理由・具体的な手順を示す。
- 基本手順では有料プランや有料サービスを前提にしない。

## 2. ツール選定
ツールを紹介するときは、可能な範囲で以下を記載する。
1. 目的と導入する意義
2. 比較した候補と比較観点
3. 採用した候補と選定理由
4. 公式配布先・公式案内
5. 無料利用の範囲、制限、必要な権限、安全上の注意
6. 導入・設定手順
7. 実際の使い方
8. 完了条件と確認方法
9. トラブル時の確認と代替手段
10. 確認日と検証状況

候補比較と実地検証を混同しない。試していないものを検証済みと書かない。変わり得る仕様には確認日・確認先を添え、未確認は未確認と明記する。

## 3. 標準手順の構成
原則として「目的・意義 → 候補と選定理由 → 事前準備 → 操作手順 → 期待結果 → 完了条件 → トラブル対応 → 代替手段 → 安全上の注意」の順で書く。
本文は文章・手順・コマンド中心とし、初版では図やイラストを原則使わない。

## 4. 記述の信頼性
- **標準手順**：読者に推奨する基本ルート。
- **実体験**：実際に試して分かったこと。個人の経験として書き、一般論に拡張しない。
- **要確認**：仕様・画面・料金・権限など未確認の事項。
- **代替手段**：標準手順が使えない場合の方法。

AIの回答、実施した操作、確認できた結果を区別する。未確認は「未確認」、未完了は「未完了」とする。AIの回答だけを根拠に操作や保存の成功を断定しない。

## 5. 完了条件
「設定する」「保存する」で終わらせず、何を確認すれば完了なのかを書く。読者自身がファイルを開く、内容を読み戻す、実際の画面を見るなどして判定できる条件を優先する。

## 6. 本文内検索タグ
統一語彙：`#目的`、`#選定`、`#設定`、`#使い方`、`#確認`、`#トラブル`、`#代替手段`、`#無料`、`#安全`、`#用語`。
- 節の冒頭など、見つけやすい位置に付ける。
- 関係するタグだけを付け、むやみに増やさない。
- タグは検索補助であり、具体的な見出しの代わりにはしない。
- 本文内の検索タグとnoteの公開用タグは用途を分ける。

## 7. 章構成と重複
- 各章に固有の役割を持たせ、同じ説明を繰り返さない。
- 目的・AI選定・基本ルールと、GitHub・Markdown保存・Dropbox等の個別設定を区別する。
- 重複する説明は主説明を適切な章に集約し、他の箇所では短い参照にとどめる。
- セッティングと運用を無理に分けず、読者が環境を完成させ実際に使える流れを優先する。

## 8. 公開前確認
執筆・検証メモは公開本文から分離する。公開前に、公式リンク、無料条件、権限、安全性、画面手順、完了条件、タグ、重複、公開不可情報を確認する。
