# AI作業のセッティングマニュアル（初版）

AIサービスや各ツールの画面・無料利用条件は変更されることがあります。このマニュアルでは確認先を示し、実際の画面で確認できていない操作や結果を「確認済み」とは扱いません。

## 第1章　AIで実現したいことを決め、使うAIを選ぶ

### この章の目的

AIを使って何かを実現したいとき、最初に必要なのは完璧な計画ではありません。まず何を試すかを決めるところから始まります。

このマニュアルは、AIを使った経験を積み重ね、必要なら他の人にも伝えられる形にするための実践ガイドです。設定を済ませること自体をゴールにせず、整えた環境で試し、結果を記録できるところまで進みます。有料プランや有料サービスは基本手順の前提にしません。無料公開の本拠地はGitHub Pagesとし、noteは公開後に反応や需要を確かめる候補として扱います。noteでの販売や有料化は、この初版の利用条件ではありません。

### このマニュアル群の約束：基本の実践は完全無料で

AIを使い始めること、作業環境を整えること、試行錯誤を記録すること、経験や成果を公開することまで、**基本の実践を有料プランや有料ツールなしで進められる方法**を中心に紹介します。将来、note等で有料化を検討する場合も、それは基本手順とは別の判断です。この初版の実践や無料公開に、購入を必須条件として設けません。

「完全無料」は、無料プランに制限がないという意味ではありません。無料枠の回数・容量・機能制限、サービス側の仕様変更、無料ではできないことも明記し、制限に当たったときは作業を小さくする、手動で代替する、別の無料手段を検討するなどの方法を示します。読者が知らないうちに課金を求められる構成にはしません。

### 1.1　実現したいことを一つ選ぶ

「AIで何かできないかな？」という段階でも構いません。結果を確かめられる小さな題材を選びます。

- 自分の考えをAIと相談して整理する。
- 日々の作業の一部を、AIでやりやすくできるか試す。
- AIとの対話や試行錯誤を記録し、あとから読み返せるようにする。
- 自分が試した方法を、他の人にも伝えられる手順にまとめる。

次のシートを埋めてください。決まっていない項目は「未定」で構いません。

| 項目 | 記入内容 |
|---|---|
| 実現したいこと | 何をやってみたいか |
| 試したい理由 | 興味、期待、実現したいこと |
| 最初の一歩 | 小さく試せる作業 |
| 完了条件 | 何を確認できれば今回の試行を終えられるか |
| 残したい記録 | 目的、試したこと、結果、気づき |
| 今回は扱わないこと | 初回の試行から外す範囲 |

**記入例**

| 項目 | 記入例 |
|---|---|
| 実現したいこと | AIとの相談内容を、あとから読み返せる記録にする |
| 試したい理由 | 以前試したことや、うまくいった方法を忘れたくない |
| 最初の一歩 | 短い相談を一回行い、要点をテキストファイルに残す |
| 完了条件 | 後から読んで相談内容と結論が分かる |
| 残したい記録 | 目的、試したこと、結果、次に試すこと |
| 今回は扱わないこと | 自動保存や複雑な自動化 |

### 1.2.1　筆者の実践例：ChatGPTをメインに、Claudeを切り札にする

ここでは、筆者が実際に使っている体制を一例として紹介します。全員にとっての正解や、AIの性能順位を示すものではありません。自分に合う構成を考えるときの出発点として読んでください。

- **ChatGPT：メイン担当。** 普段の相談、考えの整理、文章や手順のたたき台作りなど、日常の作業の中心にします。
- **Claude：三枚のおふだ。** メインのAIだけでは行き詰まったときや、別の視点がほしいときに使う切り札として温存します。筆者の利用経験では無料枠の制限を強く感じるため、何でもClaudeに頼むのではなく、必要な場面を選びます。「三枚のおふだ」は、この例ではClaudeだけを指します。
- **自分（使う本人）：最終判断者。** AIの答えをそのまま正解とせず、提案を読み、必要な事実や操作結果を確認し、採用するかどうかを決めます。

この組み合わせが筆者にはうまく機能していますが、使い方、好み、無料枠で足りる範囲、有料プランを許容できるかどうかは人それぞれです。まず一つのAIだけで始めても、別のAIをメインにしても、複数のAIを役割分担させても構いません。有料プランへの加入を前提にせず、自分の条件で続けられる構成を選びます。

無料枠の上限や利用できる機能は変わることがあります。筆者の経験を現在の全利用者に当てはまる仕様として扱わず、使う時点の公式案内と実際の画面で確認してください。候補を増やすこと自体を目的にせず、今の構成で困った場面が出たら、追加のAIを試すか考えます。

### 1.3　AIに任せることと、自分で確認することを分ける

AIは考えの整理、案出し、文章や手順のたたき台作成を助けます。一方、AIが正しいと答えたことだけでは、事実や操作結果の証明になりません。メインのAIと予備のAIを使い分ける場合も、どちらか一方の答えだけで判断を確定しないことが大切です。

- AIに任せること：相談、案出し、文章整理、手順案の作成。
- 自分で確認すること：実際の操作結果、重要な事実、サービスの現在の仕様、公開・共有の範囲。
- 記録に残すこと：自分が実施したこと、確認できた結果、まだ分からないこと。
- 最終的に決めること：AIの提案を採用するか、追加確認するか、見送るか。

最初から複数のAIを同時に使う必要はありません。まず一つの目的を一つのAIで試し、必要が出てから別の候補を検討します。筆者の「ChatGPTをメインに、Claudeを切り札にする」体制も、そうした選択肢の一つです。

### 1.4　最初の試行を決める

最初から小さな作業や確認条件を決められなくても構いません。「こういうことをやりたい。できる？」という問いから始めても大丈夫です。AIと相談しながら、まず試す小さな作業と確認したい条件を整理します。決まったら、次の形式で最初の試行を一文にします。

```text
私は［実現したいこと］のために、まず［小さな作業］を試す。
［確認したい条件］を満たせば、今回の試行は完了とする。
結果と未確認事項を記録し、次に試すことを一つ決める。
```

### この章の完了条件

- [ ] 実現したいことを一つ選んだ。
- [ ] 最初の一歩と完了条件を書いた。
- [ ] AIの候補を比較する観点を理解した。
- [ ] 採用したAIと選んだ理由を記録できる状態にした。
- [ ] AIの提案と、自分で確認した事実を区別した。

この章では目的とAIの選定までを行います。アカウント、保存先、ファイル管理などの具体的な環境設定は、次章以降で手順に沿って進めます。

## 第2章　AIを使う環境を整え、作業を再開できるようにする

### この章の目的

設定をする理由は、ツールを入れること自体ではありません。試したことを失わず、次に何をすればよいか分かり、必要なときに作業を再開できるようにするためです。

この章では、ChatGPTの登録・ログインから最初の会話までを具体的に試し、Claudeを必要時に使えるよう準備します。Geminiは必要に応じて追加します。そのうえで、入力情報の扱い、回答の確認、作業の記録方法を整えます。GitHub、会話のMarkdown保存、Dropboxの操作は、それぞれの章で扱います。

### 2.1　作業を始める前に

#### 2.1.1　今回の目的と作業範囲

作業を始める前に、今回の目的、扱う範囲、今回扱わないことを短く整理します。最初からすべてを細かく決める必要はありません。まずは、試したいことと、今回どこまでできればよいかを決めます。

#### 2.1.2　使用するAIと無料利用の条件

このマニュアルでは、ChatGPTを普段の作業相手、Claudeを必要なときに別の視点を得る選択肢として扱い、Geminiは補助候補として紹介します。最初からすべてのサービスを使う必要はありません。無料プランの利用範囲や上限は変わることがあるため、利用する時点の公式案内と実際の画面で確認してください。基本手順では有料プランを前提にしません。

#### 2.1.3　入力してよい情報・保存先・完了条件

AIに渡してよい情報と渡さない情報、結果を保存する場所、作業の完了を判断する方法を確認します。パスワードやトークンなどの秘密情報を入力せず、必要に応じて架空の例や機密情報を除いた抜粋を使います。今回の作業に関係する条件だけを短く決めれば十分です。

### 2.2　AIサービスを準備する

#### 2.2.1　ChatGPTを準備し、最初の会話をする

##### 2.2.1.1　公式サイトを開く

[ChatGPT公式サイト](https://chatgpt.com/)を開きます。公式サイトかどうかを確認してから操作してください。

##### 2.2.1.2　登録またはログインする

すでにアカウントがある場合は新規登録せず、ログインします。初めて利用する場合は、画面の［サインアップ］などの案内に従って登録します。メール確認などが表示された場合も、公式画面の指示に従ってください。認証コードやパスワードをAIとの会話や記録ファイルへ貼り付けてはいけません。

##### 2.2.1.3　無料利用の範囲・制限とデータ設定を確認する

無料利用の範囲と利用上限は、[ChatGPT無料版の公式案内](https://help.openai.com/ja-jp/articles/9275245-chatgpt-%E7%84%A1%E6%96%99%E7%89%88%E3%81%AB%E9%96%A2%E3%81%99%E3%82%8B%E3%82%88%E3%81%8F%E3%81%82%E3%82%8B%E8%B3%AA%E5%95%8F)と実際の画面で確認します。ツールごとに利用上限が異なり、内容も変更されるため、固定の回数を前提にしません。データ設定は[公式のデータコントロール説明](https://help.openai.com/ja-jp/articles/7730893-data-controls-in-chatgpt)を参照してください。ウェブ版でログインしている場合は、アカウントメニューから［設定］→［データコントロール］を開き、必要に応じて［すべての人のためにモデルを改善する］をオフにします。これは新しい会話をモデル学習に使用しないための設定であり、会話履歴の削除や、あらゆる保存・処理の停止を意味するものではありません。設定名や表示は実際の画面と最新の公式案内を優先してください。

##### 2.2.1.4　最初の会話を行い、回答を確認する

機密情報を含まない短い文章で会話を試します。例えば、次のように依頼できます。

```text
次の文章を、意味を変えずに箇条書きで整理してください。
```

回答を読み、目的に合っているか確認します。必要なら依頼を言い換えてみてください。登録画面やボタン名は変更されることがあるため、表示が異なる場合は現在の公式案内を優先します。

##### 2.2.1.5　普段の作業相手として使う

普段の作業では、やりたいこと、分からないこと、試したいことをそのまま相談して構いません。例えば「この作業の目的と、最初に試す小さな一歩、完了したか確認する方法を一緒に整理して」と頼み、作業を小さく分けて進めます。最初から完璧な依頼文を用意する必要はありません。

##### 2.2.1.6　別のAIに相談するための依頼文を作成する

普段使っているAIに、別のAIへ相談するための依頼文を作ってもらうこともできます。例えば、次のように頼みます。

```text
Claudeにこの件を相談しようか？ 依頼文出して。
背景、相談したいこと、守ってほしい条件、確認してほしい点を含めて。
```

生成された依頼文を読み、秘密情報や不要な個人情報が含まれていないことを確認してからコピーし、Claudeの会話欄へ貼り付けます。AIが作った依頼文も、そのまま送信せず、自分で内容を確認してください。

#### 2.2.2　Claudeを準備し、最初の会話をする

##### 2.2.2.1　公式サイトを開く

[Claude公式サイト](https://claude.ai/)を開きます。公式サイトかどうかを確認してから操作してください。

##### 2.2.2.2　登録またはログインする

すでにアカウントがあればログインし、初めて利用する場合は画面の案内に従って登録します。メール確認などが求められた場合は、公式画面の指示に従ってください。認証情報を会話や記録ファイルへ貼り付けないでください。

##### 2.2.2.3　無料利用の範囲・制限とプライバシー設定を確認する

[公式のプラン案内](https://claude.com/pricing)で無料プランの機能と利用上限を確認し、[プライバシーに関する公式説明](https://support.claude.com/ja/articles/8325621-claude%E3%81%A8%E3%81%AE%E3%83%81%E3%83%A3%E3%83%83%E3%83%88%E3%81%AB%E6%A9%9F%E5%AF%86%E3%83%87%E3%83%BC%E3%82%BF%E3%82%92%E5%85%A5%E5%8A%9B%E3%81%97%E3%81%9F%E3%81%84%E3%81%A8%E3%81%8A%E3%82%82%E3%81%84%E3%81%BE%E3%81%99-%E7%A7%81%E3%81%AE%E4%BC%9A%E8%A9%B1%E3%82%92%E8%AA%B0%E3%81%8C%E9%96%B2%E8%A6%A7%E3%81%A7%E3%81%8D%E3%82%8B%E3%81%AE%E3%81%A7%E3%81%97%E3%82%87%E3%81%86%E3%81%8B)を読みます。無料プランにも利用上限があり、利用できる機能や上限は変更されることがあります。プライバシー設定の表示は実際の画面と最新の公式案内を優先してください。

##### 2.2.2.4　最初の会話を行い、回答を確認する

機密情報を含まない質問を一つ入力し、回答を確認します。例えば「この説明で分かりにくいところを挙げ、改善案を示してください」と依頼できます。回答は一つの意見として読み、必要な点は別の情報源や実際の結果で確認してください。

##### 2.2.2.5　必要なときに別の視点を得る

Claudeは、普段のAIだけでは判断しにくいときや、別の視点がほしいときに使う選択肢です。筆者は必要な場面を選ぶ「切り札」として使っています。これは筆者の経験に基づく使い分けであり、すべての人に当てはまる評価ではありません。

#### 2.2.3　Geminiを補助的な選択肢として紹介する

##### 2.2.3.1　公式サイトと利用条件の確認先を示す

[Gemini公式サイト](https://gemini.google.com/)を開きます。利用条件やデータの扱いは、[Geminiアプリのプライバシーハブ](https://support.google.com/gemini/answer/13594961?hl=ja)と[アクティビティ管理](https://support.google.com/gemini/answer/13278892?hl=ja-JP)で確認できます。ログイン手順は[公式のログイン案内](https://support.google.com/gemini/answer/13278668?hl=ja)を参照してください。アクティビティの保存をオフにしても、サービス提供や安全性のために会話が処理される場合があるため、機密情報は入力しないでください。

##### 2.2.3.2　必要に応じて登録・ログインする

利用する場合は、画面の案内に従ってGoogleアカウントでログインします。利用可能な機能や条件はアカウントや時期によって変わることがあるため、現在の画面を確認してください。

##### 2.2.3.3　最初の会話を試す

機密情報を含まない短い質問を入力し、回答を確認します。重要な判断は回答だけで確定せず、必要に応じて別の情報源や実際の結果を確認してください。

##### 2.2.3.4　補助的な選択肢として紹介する

最初からGeminiを使う必要はありません。ChatGPTやClaudeで目的を試せるなら、Geminiは別の視点が必要な場合などに検討する補助候補として扱います。筆者自身の利用経験と、サービスの仕様として確認できた事実は区別してください。

### 2.3　AIを使う上での注意事項

#### 2.3.1　秘密情報や不要な個人情報を入力しない

パスワード、アクセストークン、Cookie、セッション情報、秘密鍵などの認証情報は、AIへの依頼文や公開ファイルへ貼り付けません。他人の個人情報や、共有・公開する権利のない資料も、必要性と扱いを確認せずに入力しないでください。

実際の情報を使わなくても目的を達成できる場合は、架空の例や機密情報を除いた抜粋で試します。記録を保存するときも、秘密情報が混ざっていないか確認します。

#### 2.3.2　AIの回答を実際の結果と混同しない

AIを使って何かを始めるとき、記録や管理の仕組みを自分で用意する必要はありません。

やりたいこと、試したこと、うまくいかなかったこと、分からないことなどを、普段使っているAIとの会話に書き込んでいけば大丈夫です。きれいにまとめてから書く必要もありません。

同じ会話を参照できる間は、AIにこれまでの経緯や次に試すことを整理してもらえます。ただし、会話履歴や以前の内容をいつでも参照できるとは限りません。大事な作業の結果や次回に必要な情報は、必要に応じて別のファイルにも保存してください。

ただし、AIが「保存できた」「完了した」と答えたことと、実際に保存や操作が成功したことは別です。大事な結果は、必要に応じて画面やファイルなどで確認しましょう。まだ確かめていないことは、無理に結論を出さず「未確認」のままで構いません。

まずは、AIに書き込みを依頼して進めてみる。それだけで始められます。

#### 2.3.3　外部に影響する操作は、内容を確認してから行う

ファイルの削除や上書き、公開、共有、権限変更など、ほかの人や外部サービスにも影響する操作は、少しだけ慎重に進めましょう。

難しい判断をすべて自分で行う必要はありません。例えば、次のようにAIに相談できます。

「この操作をすると何が変わる？　影響する範囲と、実行前に確認したほうがよいことを教えて」

AIに説明や確認項目を整理してもらい、内容を理解してから進めれば十分です。迷ったときは、すぐに実行せず、もう一度AIに質問して構いません。

なお、変更案を作ること、実際に保存すること、変更を取り込むこと、公開先に反映することは、それぞれ別の段階です。AIに手伝ってもらいながら、一つずつ結果を確認していきましょう。

#### 2.3.4　無料プランの制限と仕様変更に備える

無料プランでは、利用回数や使える機能などに制限がある場合があります。でも、制限に当たったからといって、すぐに有料プランへ切り替える必要はありません。

まずは、AIにこう相談してみましょう。

「今の無料プランで続けたい。制限に当たったとき、課金せずに続ける方法を一緒に考えて」

作業を小さく分ける、文章中心で進める、手作業で代わりに行う、別の無料ツールを試すなど、できることを一緒に整理できます。

ただし、AIの説明が現在の利用条件と一致するとは限りません。具体的な回数や機能を確認するときは、AIに公式の確認先を教えてもらい、実際の案内や画面を確認してください。分からない点は「未確認」で構いません。

**最初から全部の制限を調べておく必要はありません。困ったときにAIと調べればよい**、というくらいの気持ちで始めましょう。

#### 2.3.5　中断時は試行記録を短くして残す

作業を中断するときに、長い記録を自分で書く必要はありません。AIに、次に再開できる形でまとめてもらいましょう。

例えば、次のように頼めます。

「ここで作業を中断する。今回やったこと、確認できた結果、まだ終わっていないこと、次にやることを、再開しやすいように短くまとめて」

AIがまとめた内容を読んで、大きな間違いがないか確認すれば十分です。必要に応じて、そのまとめをファイルに保存したり、会話そのものをMarkdownで保存したりできます。

毎回、決まった様式を完璧に埋める必要はありません。短いメモでも、次に何をすればよいか分かれば役に立ちます。

なお、パスワードやアクセストークンなどの認証情報、保存する必要のない個人情報は記録に含めないでください。

まずはAIに相談しながら一度やってみる。それで足りないと感じたら、少しずつ記録や管理の方法を整えていけば大丈夫。

### この章の完了条件

- [ ] 今回の目的と作業範囲を決めた。
- [ ] 使用するAIの準備を行い、少なくとも一つのサービスで最初の会話を試した。
- [ ] ChatGPTとClaudeの準備方法と役割の違いを理解した。
- [ ] Geminiは必要に応じて使う補助的な選択肢であると理解した。
- [ ] 入力してはいけない情報と、外部操作の前に確認することを理解した。
- [ ] AIの回答と実際に確認できた結果を区別できる。
- [ ] 作業を中断するときに、再開に必要な試行記録を残せる。

次章では、実際の記録をGitHubで管理し、ファイルの保存と変更履歴を確認する手順へ進みます。

## 第3章　GitHubで記録と変更履歴を管理する

### この章の目的

この章では、AIとの試行錯誤で生まれたメモや手順を、後から見つけて再利用できる形で管理する方法を学びます。GitHubの機能を最初から一通り覚えることが目的ではありません。何を残すかをAIと相談し、必要なファイルをAIに作ってもらい、自分で内容を確認して保存するところから始めます。

GitHubの画面や無料プランの仕様は変わることがあります。ボタン名や利用可能な機能が本文と違う場合は、現在の画面と公式案内を優先してください。

### 3.1　なぜGitHubを使うのか

この環境づくりで目指したのは、人と3つのAI（ChatGPT・Claude・Gemini）が、共通の情報を読み書きしながら協力できることです。作業の目的、決定事項、運用ルール、手順などをファイルにまとめ、AIとの会話が変わっても必要な情報を引き継げる仕組みを目指しました。

保存先を検討した際、Google系のサービスやAPIを利用する方法も候補になりました。しかし、今回の環境では、ChatGPT無料版から想定していたGoogle系APIを利用する構成は実現できませんでした。また、GeminiからGitHubを直接読み書きすることもできませんでした。

そこで、Claude・ChatGPT・人がGitHub上のファイルを読み書きしながら作業を進め、Geminiとの間は必要なファイルをコピー＆ペーストして受け渡す方法で補うことにしました。すべてのAIが同じ方法で直接アクセスできるわけではありませんが、人が橋渡しすることで、共通の情報を使った共同作業を目指します。

GitHubを選んだのは、すべてのAIと直接連携できるからではありません。目指す運用と、実際に利用できたサービスの機能・制約を踏まえ、運用可能な方法として判断したためです。GitHubにはファイルの変更履歴を残せる利点もあり、必要に応じて以前の状態や変更内容を確認できます。

この判断は、環境を構築した時点でのものです。AIの機能や各サービスの連携条件は今後変わる可能性があります。将来、より簡単に連携できる方法が利用可能になれば、運用を見直す余地があります。

この方法が唯一の正解というわけではありません。保存先には、ほかにも次のような候補があります。

| 候補 | 向いている用途 | 今回の目的から見た特徴 |
| --- | --- | --- |
| PC内のフォルダー | 手元でファイルを簡単に整理する | 始めやすい一方、複数のAIとの受け渡しや、別の端末からの利用は別途工夫が必要 |
| Google Drive・OneDriveなど | ファイルを同期・共有する | 手軽に共有できるが、AIから直接読み書きできるかは、利用するAI・プラン・連携機能に左右される |
| Notionなどの情報管理サービス | ページ単位でメモや知識を整理する | 情報をまとめやすいが、Markdownファイルを中心にAIと共同管理する今回の運用とは使い方が異なる |
| GitHub | テキストファイルを管理し、変更履歴を残す | Claude・ChatGPT・人がファイルを行き来する基盤として使え、Geminiとはコピー＆ペーストで橋渡しできる |

この比較は一般的な優劣を示すものではありません。利用できるAI連携、料金、操作のしやすさは変わるため、実際に使う環境で確認します。今回は、すべてのAIが直接つながる保存先を見つけることよりも、制約があっても共通のファイルを使って作業を続けられることを優先しました。

### 3.2　GitHubで管理するものをAIと一緒に決める

最初からフォルダーやファイルの構成を自分だけで決める必要はありません。まず、何を試していて、あとから何を読み返したいのかをAIに伝え、管理するものを相談して決めます。

例えば、次のようなものが候補になります。

- 自分が試したいことと、その目的
- AIに依頼したプロンプトや、再利用したい依頼テンプレート
- 試した手順、得られた結果、うまくいかなかった点
- 自分で確認した事実と、まだ確認できていないこと
- 次に行う作業や、作業を再開するときに役立つ説明

会話全文をすべてリポジトリに入れる必要はありません。何を残すかは、用途と公開範囲に合わせて決めます。公開リポジトリに置くものは、他の人に見られても問題がない内容に限ります。

**AIへの相談プロンプト例**

```text
GitHubを使って、AIと一緒に進めた作業や成果を記録していきたいです。

今後も役立つように残しておくとよい情報やファイルを、私と相談しながら決めてください。

最初から複雑な構成にはせず、必要最小限から始めたいです。
候補と、それぞれを管理する理由を説明し、私の使い方を確認しながら提案してください。

公開してよい情報と、非公開で管理すべき情報も分けて考えてください。
```

AIの提案をそのまま採用する必要はありません。自分の目的に合うかを確認し、分からない点は質問してから、管理対象や構成を決めます。

### 3.3　アカウントとリポジトリを確認する

すでにGitHubアカウントを持っている場合は、新しく作り直す必要はありません。まず、ログインできることと、今回使うリポジトリを開けることを確認します。

1. ブラウザーで[GitHub](https://github.com/)を開き、自分のアカウントにログインします。
2. 作業に使うリポジトリを開きます。リポジトリは、関連するファイルと変更履歴をまとめて管理する場所です。
3. リポジトリ名と所有者を確認します。似た名前の別リポジトリで作業しないようにします。
4. リポジトリの公開・非公開の状態を確認します。公開リポジトリに追加した内容は、原則として他者から閲覧できる前提で扱います。
5. 自分に変更権限があるか確認します。閲覧できることと、変更できることは同じではありません。

新しいリポジトリの作成操作は、3.3.1「ブラウザーだけで初期セットアップを完了する」で説明します。すでにリポジトリがある場合は、上の確認を済ませてから3.4へ進んでください。

GitHub Freeでは、GitHub Pagesを利用できる条件がリポジトリの公開範囲などに左右されます。公式案内で、利用中のプランと公開方法を確認してください：[GitHub Pagesの概要と利用条件](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)。公開用のページを公開するために、個人記録のリポジトリ全体を公開する必要はありません。

リポジトリの公開・非公開を後から変更すると、公開ページやフォークなどに影響する場合があります。特に、非公開化するとGitHub Freeで公開中のPagesサイトが非公開化・停止される場合があるため、変更前に[リポジトリの公開範囲変更に伴う影響](https://docs.github.com/en/repositories/managing-your-repositorys-settings-and-features/managing-repository-settings/setting-repository-visibility)を確認してください。

#### 3.3.1　ブラウザーだけで初期セットアップを完了する

この節では、追加ソフトをインストールせず、GitHubのWeb画面だけでアカウント確認・リポジトリ作成・README保存まで進めます。GitやGitHub Desktop、SSH鍵の設定は必須ではありません。画面の表示名は変更されることがあるため、項目名が異なる場合は現在の画面と[GitHub公式ヘルプ](https://docs.github.com/ja/repositories/creating-and-managing-repositories/creating-a-new-repository)を確認してください。

**手順1：ログインする**

1. [GitHub](https://github.com/)を開きます。
2. アカウントがある場合は「Sign in」からログインします。初めての場合は「Sign up」からアカウントを作成し、メールアドレスの確認が求められたら完了させます。

**手順2：新しいリポジトリを作る**

1. GitHub画面右上の「＋」を開き、「New repository」を選びます。見つからない場合は、アカウントメニューや公式ヘルプから新規作成画面を開いてください。
2. 「Owner」が自分のアカウントになっていることを確認します。
3. 「Repository name」に、何を保存する場所か分かる名前を半角英数字とハイフンで入力します。例えば、AIとの個人作業記録なら `ai-work-notes`、公開用の手順やサンプルなら `ai-work-examples` です。すでに使われている名前などで作成できない場合は、用途が分かる別の名前に変えます。
4. 必要なら「Description」に用途を一文で入力します。例：`AIとの作業記録と次回の再開メモ`。
5. 「Choose visibility」で公開範囲を選びます。**AIと共有するからといって、常にPublicが必須というわけではありません。** AIの連携機能がPrivateリポジトリへのアクセスに対応し、必要な権限が設定されているならPrivateを使えます。AIにリポジトリのURLを渡して参照させるだけの方法では、Privateの中身を読めない場合があります。その場合でも、個人記録をPublicに変えるのではなく、公開してよい内容だけを別のPublicリポジトリに分けるか、必要な文章をコピーしてAIに渡してください。
   - **Private（非公開）**：個人の作業記録、未公開の下書き、個人情報を含む可能性がある内容向け。アクセス権のある人・連携だけが閲覧できます。
   - **Public（公開）**：誰でも閲覧できる前提で公開してよい手順やサンプル向け。パスワード、トークン、秘密情報、公開許可のない個人記録は置きません。
6. READMEを最初から作る場合は「Add a README file」にチェックを入れます。最初はREADMEなしで作成してもかまいません。
7. 画面下部の「Create repository」を押します。

**手順3：作成結果を確認する**

1. 作成後に開いたリポジトリのトップ画面で、ページ上部の所有者名とリポジトリ名が、手順2で選んだものと一致していることを確認します。URLも `https://github.com/所有者名/リポジトリ名` の形になっています。
2. リポジトリ名の近くにある「Public」または「Private」の表示を確認し、選んだ公開範囲と一致していることを確かめます。
3. READMEを作成した場合は、トップ画面のファイル一覧に `README.md` があり、下部に本文が表示されることを確認します。

**手順4：READMEを後から作る（最初に追加しなかった場合）**

1. リポジトリのトップ画面で「Add file」→「Create new file」を選びます。
2. ファイル名の欄に `README.md` と入力します。
3. 本文欄に、例えば次の内容を入力します。

   ```markdown
   # AI Work Notes

   このリポジトリの目的：
   保存するもの：
   公開範囲と注意点：
   ```

4. ページ下部の「Commit changes」欄で、変更内容の説明に `Add README` などと入力します。
5. 保存先ブランチと変更内容を確認し、「Commit changes」を押します。
6. リポジトリのトップ画面へ戻り、`README.md` が一覧に表示され、本文が読めることを確認します。

ここまでできれば、GitHub上でファイルを管理するための最小限の初期セットアップは完了です。次の節では、AIにMarkdownファイルを作ってもらい、保存して内容を確認する手順に進みます。

### 3.4　MarkdownファイルをAIに作ってもらう

Markdownは、見出しや箇条書き、リンク、コードなどを、基本的にはプレーンテキストで記述する形式です。専用の編集ソフトがなくても作成でき、GitHub上でも内容を確認しやすいため、このマニュアルでは原稿の正本形式として使います。

最初から自分で本文を一から書かなくても構いません。先に自分でフォルダーを用意し、そのフォルダーの目的や、どんな情報を残したいかをAIに伝えて、README.mdなどのファイルを作ってもらう方法があります。例えば、フォルダーは自分で作り、そのフォルダーを説明するREADMEはAIに作成してもらう、という進め方です。

**AIへの作成プロンプト例**

```text
このフォルダーのREADME.mdを作成してください。

フォルダー名：
［フォルダー名を記入］

このフォルダーの目的：
［何を保存・管理する場所なのかを記入］

初めて読む人にも用途が分かるように、次の内容を整理してください。
- このフォルダーの目的
- ここに保存するもの
- ファイルの追加・更新方法
- 使い方や注意点

まだ決まっていないことは勝手に確定せず、必要なら質問してください。
内容は分かりやすく簡潔にし、Markdown形式で作成してください。
```

AIが出力した本文を読み、目的に合っているか、事実と違う説明がないか、決まっていないことを勝手に決めていないか確認します。修正したいところがあればAIに直してもらいます。AIがGitHubに直接ファイルを作成できる連携環境を使っていない場合は、生成されたMarkdown本文を自分でコピーしてファイルに貼り付けます。

ファイルを保存する方法は、作業環境に応じて選べます。

- **GitHubのWeb画面で作成する場合**：対象リポジトリで「Add file」から「Create new file」などを選び、ファイル名に `README.md` または `フォルダー名/README.md` を入力して、AIが作成した本文を貼り付けます。画面に表示される保存先・ブランチ・変更内容を確認してから「Commit changes」などの保存操作を行います。
- **PC上で作業する場合**：自分で作ったフォルダーに、AIが作成した本文を `README.md` として保存し、普段使っている方法でGitHubへ反映します。

保存後は、ファイルが意図した場所に表示されること、見出しや箇条書きが読めること、本文が欠けていないことを確認します。ファイルが見当たらない場合は、リポジトリ・ブランチ・パスを確認します。原因が分からないときは元の本文を残し、同名ファイルを重複作成する前に保存状態を確認してください。

### 3.5　変更履歴は、必要になったときに確認する

GitHubには、ファイルの変更を記録し、後から何が変わったかをたどる仕組みがあります。その記録の単位の一つが「コミット」です。変更内容を説明する短いメッセージを付けておくと、後から目的を思い出しやすくなります。例えば「READMEにフォルダーの使い方を追記」のように書きます。

この段階で、変更履歴の画面を開く操作まで覚える必要はありません。まずは、ファイルを保存したあとに内容が意図どおりかを確認できれば十分です。後から「何を変えたか分からない」「以前の内容と比べたい」となったときに、GitHubの変更履歴や差分を確認する方法を学べば構いません。必要ならAIに、今の画面で変更履歴を確認する手順を尋ねてもよいでしょう。

### 3.6　ブランチとPull Requestを知る

複数の変更を安全に扱いたい場合は、ブランチとPull Requestを利用できます。

- **ブランチ**：既存の状態を基に、変更を分けて進めるための作業線です。
- **Pull Request（PR）**：ブランチ上の変更案を、別の人や自分自身で確認してから取り込むための提案です。
- **レビュー**：変更内容を読み、目的との整合、誤り、漏れ、危険がないかを確認することです。
- **マージ**：確認された変更を、取り込み先のブランチへ統合することです。

一人で作業していても、PRを使うと、変更案を確定する前に差分を確認できます。PRを作成しただけでは、変更が取り込み先へ反映されたとは限りません。レビュー状態、必要なチェック、マージ済みかどうかを別々に確認してください。

大切なファイルを変更するときは、可能であれば変更案をPRとして提示し、内容とチェック結果を確認してから取り込みます。リポジトリごとに保護ルールや承認条件が異なるため、そのリポジトリで設定されている条件に従います。

### 3.7　保存先・公開範囲・認証情報に注意する

保存先は、公開範囲と役割で選びます。同じファイルを最初から複数の場所へ複製せず、まず正本を一つ決めると、更新漏れを減らせます。

| 情報の種類 | 保存先の基本方針 | 確認すること |
| --- | --- | --- |
| 個人の作業記録・未公開の下書き | 非公開リポジトリ、または自分のDropboxアカウント | アクセス権、共有状態、公開してよい内容か |
| 公開してよい手順・サンプル | 公開用GitHubリポジトリ | 公開してよい内容だけか、履歴にも秘密情報がないか |
| 公開ページ | GitHub Pagesなどの公開先 | 原稿の保存とは別に、公開ページの表示を確認 |
| パスワード・APIキー・アクセストークン・秘密鍵・Cookieなどの認証情報 | 通常の記録ファイルやリポジトリには保存しない | 誤って公開した場合は、ファイル削除だけで済ませず、該当する認証情報を失効・再発行する |

公開リポジトリに追加した内容は、原則として誰でも閲覧できるものとして扱ってください。パスワードやトークンなどの認証情報を、リポジトリのファイルに記録してはいけません。秘密情報が一度コミットされると、ファイルを後から削除しただけでは履歴から消えない場合があります。誤ってコミット・公開した場合は、公開された情報を消すだけでなく、該当する認証情報を失効・再発行してください。

Dropboxを使う場合は、正本として管理するのか、保管用コピーとして使うのかを先に決めます。Dropboxへ保存しただけでGitHubの正本が更新されたことにはなりません。公開物をGitHub Pagesで公開する場合も、個人記録とは分けた公開用リポジトリを使います。

GitHub Pagesの利用条件はプランやリポジトリの設定により異なります。無料での公開を始める前に、[GitHub Pagesの公式利用条件](https://docs.github.com/en/pages/getting-started-with-github-pages/what-is-github-pages)を確認してください。

## 第4章　ChatGPTのチャットをMarkdownで保存する準備

AIとのやり取りを後から読み返し、試したことを記録として残せるように、チャットをMarkdown形式で保存する準備をします。ブラウザー拡張機能はチャット内容を読み取れる権限を求める場合があるため、便利さだけで選ばず、提供元・権限・プライバシー説明を確認してから使います。この章では特定の拡張機能を無条件には推奨しません。

チャット単位で最後に保存する方法に落ち着いたのは、実際の運用で試行錯誤した結果です。初めは、決定や進捗が出るたびにAIへ記録を書き込むよう指示していました。しかし、記録作業と通常の作業、さらに報告などの指示が重なると、記録が実行されなかったり、確認や修正に追われて本来の作業が止まったりすることがありました。何ターンかごと、あるいは作業の区切りで保存する方法も試しましたが、直前のやり取りが抜けることがあり、安定しませんでした。

そこで、チャットを閉じるときに、チャット全体をまとめて書き出す方法に落ち着きました。途中の記録指示を減らして作業の流れを保ちつつ、会話を抜けなく残すためです。基本はチャット全体を保存し、部分保存は必要な場合に限ります。書き出した後はファイルを開き、内容が残っているか確認します。

4. **権限**：ChatGPTのページだけでなく、すべてのWebサイトのデータを読み取る権限など、機能に比べて広い権限を求めていないか確認する。

ストアに掲載されていることやレビュー評価だけで、安全性が保証されるわけではありません。プライバシー説明が見つからない、内容が曖昧、必要な機能に対して権限が広すぎると感じる場合は、インストールを見送ってください。


3. 「プライバシー」欄と権限の説明を読み、内容に納得できなければ使用しない。
4. **未インストールの場合だけ**「Chromeに追加」を選び、ブラウザーが表示する権限要求を読む。すでにインストール済みなら、この操作や再インストール・更新を検証のために行わない。説明と異なる広い権限を求められたら中止して再確認する。
5. ChatGPTで、機密情報を含まないテスト用会話を開く。
6. ブラウザーの拡張機能メニューから、識別した拡張機能を開く。同名・類似名の候補があるため、管理画面で記録した名前・IDと一致するものを選ぶ。

## 第5章　Dropboxで記録を整理する

### この章の目的

AIとの試行錯誤で生まれたファイルを、後から見つけて使い直せるように整理します。ここではDropboxを保管・受け渡し用の場所として扱い、正本とコピーを混同しないための基本を決めます。Dropboxを使わない場合も、同じ考え方を自分の保管場所に適用できます。

### 5.1　Dropboxを使う前に保存先を決める

保存先を増やすほど安心になるとは限りません。どこが正本か分からなくなり、更新漏れが起きることもあります。まず、ファイルごとに正本を一つ決めます。

| 情報の種類 | 保存先の基本方針 | 注意点 |
| --- | --- | --- |
| 個人の作業記録・未公開の下書き | 非公開リポジトリ、または自分のDropboxアカウント | 共有リンクを作らず、アクセス範囲を確認する |
| 公開してよい手順・サンプル | 公開用GitHubリポジトリ | 個人記録や秘密情報と分ける |
| 公開ページ | GitHub Pagesなどの公開先 | 原稿の保存とは別に表示を確認する |
| パスワード・トークン・秘密鍵 | 通常の記録ファイルには保存しない | 誤公開した場合は認証情報を失効・再発行する |

Dropboxを使わない場合は、PC上の自分が管理できるフォルダーでも構いません。Dropboxを保管用コピーとして使う場合は、正本を更新する場所とコピーを分けて記録します。初回から同じファイルを複数箇所へ複製せず、必要性が出てからコピーを追加します。

### 5.2　Dropboxの無料アカウントを準備する

Dropboxを初めて使う場合は、[Dropbox公式サイト](https://www.dropbox.com/)を開き、アカウントを作成するかログインします。無料のDropbox Basicには容量制限があります。公式案内では2 GBとされていますが、プランや条件は変更されることがあるため、[Dropbox Basicの容量と超過時の扱い](https://help.dropbox.com/ja-jp/storage-space/over-quota)で利用時点の条件を確認してください（公式案内確認日：2026-10-14）。

アカウントを用意したら、今回の記録を保存するフォルダーを一つ作ります。最初から細かい分類を増やす必要はありません。

### 5.3　ファイルをDropboxへアップロードする

1. [Dropbox](https://www.dropbox.com/)にログインし、保存先のフォルダーを開きます。
2. 画面の［アップロード］から［ファイル］または［フォルダ］を選び、保存するファイルを指定します。
3. アップロードが終わったら、表示されたファイル名を確認して開き、内容が正しいことを確かめます。
4. 共有が不要なら共有リンクを作らず、共有設定が意図しない状態になっていないか確認します。

詳しい画面操作は[Dropbox公式のアップロード手順](https://help.dropbox.com/ja-jp/create-upload/add-files)を参照してください。画面名が変わっている場合は公式案内を優先します。

保存できない、ファイルが見つからない、同期が止まっている場合は、保存先のアカウントとフォルダー、ネット接続、容量の残り、アップロード表示を確認します。ファイルを再度アップロードする前に、同名ファイルや重複ファイルができていないか確認してください。原因が分からなければ、PC上に元ファイルを残し、未完了として記録します。

### 5.4　Dropboxに保存するものを選ぶ

すべてのAIチャットを無条件に保存する必要はありません。後から再開・再利用する価値があるものを選びます。

- 試した手順と、実際に確認できた結果
- 再利用したいプロンプトや作業テンプレート
- 次に作業を再開するための区切り記録
- 必要な場合の、公開して問題のない会話記録
- 正本とは別に保管しておく必要があるファイル

パスワード、APIトークン、Cookie、セッション情報などの認証情報は保存しないでください。第三者の個人情報や、公開許可のない仕事上の情報も、保存の必要性と適切な保護方法を確認せずに持ち込まないでください。

### 5.5　フォルダーを少なく分かりやすくする

最初から細かい分類を作りすぎず、まずは少数のフォルダーで始めます。例えば、次のような構成です。

```text
AI記録/
├─ 01_作業中/
├─ 02_試行記録/
├─ 03_再利用テンプレート/
└─ 99_一時保管/
```

この構成は例です。分類に迷うファイルは、ひとまず一時保管へ置き、後で必要性を判断します。一時保管を恒久的な置き場にしないよう、定期的に中身を見直します。

フォルダー名は、自分が見て意味を判断できる言葉にします。階層を深くしすぎると保存先を探しにくくなるため、必要が出てから分類を増やします。

### 5.6　ファイル名に日付と内容を入れる

ファイル名だけで内容と時期を大まかに判断できるようにします。例えば、次のような形式です。

```text
YYYY-MM-DD_作業テーマ_記録.md
2026-10-14_文章整理_試行記録.md
2026-10-14_再開用_区切り記録.md
```

日付は実際に作業した日付を使い、日付が分からない場合は推測で付けないでください。同じ名前のファイルを上書きする前に、既存ファイルが必要な記録ではないか確認します。サービスの自動命名がある場合も、保存後にファイル名と中身を確認します。

ファイル名へ個人情報や秘密情報を含めないことも大切です。共有リンクを作る場合、リンク先のファイル名自体が相手に見えることがあります。

### 5.7　保存後に中身と場所を確認する

アップロード操作をしただけでは、目的の場所に正しい内容が保存されたとは限りません。保存後に、次を確認します。

1. 保存先のアカウントとフォルダーが正しい。
2. ファイル名が分かりやすく、既存ファイルを意図せず置き換えていない。
3. ファイルを開けて、内容が欠けていない。
4. Markdownの場合は、見出し・箇条書き・コードなど必要な内容が残っている。
5. 正本とコピーのどちらなのかが分かる。
6. 共有設定が意図した範囲になっている。必要がなければ共有リンクを作らない。

同期アイコンやアップロード表示だけを見て完了と決めつけず、必要なファイルを実際に開いて確認します。大切な記録を複数の場所に置く場合は、どれが正本かを明記しておきます。

### 5.8　コピーを正本へ反映する手順を決める

Dropboxで記録を整理しても、GitHubの正本が自動的に更新されるわけではありません。コピー側で内容を直した場合は、正本へ反映する必要があるかを判断し、必要なら変更案として反映して差分を確認します。

GitHubで管理している正本を更新する場合は、そのリポジトリで決められた保存手順に従い、変更案・チェック・マージの状態を確認します。Dropboxへの保存、GitHubへの変更案の提出、マージ、公開ページへの反映は別の段階です。

### 5.9　この章の確認

- [ ] 正本、コピー、作業中ファイル、公開先の役割を区別した。
- [ ] 保存する記録を選び、認証情報や公開できない情報を除外した。
- [ ] 自分が理解できる少数のフォルダーから始めた。
- [ ] 日付と内容が分かるファイル名を付けた。
- [ ] 保存後に保存先とファイルの中身を確認した。
- [ ] 共有設定を確認し、不要な共有を作っていない。
- [ ] コピー側の変更を正本へ反映する方法を決めた。

次章では、AIに何かを試してもらう前に、目的と条件を整理し、再利用できるプロンプトへ育てる方法を扱います。

## 第6章　初回のプロンプトを作る

### この章の目的

最初から完璧なプロンプトを書く必要はありません。やりたいことを言葉にし、AIと相談して小さな依頼文にするところまでを扱います。試行結果を見ながらプロンプトを繰り返し改善する方法は、後続の運用マニュアルで扱います。

### 6.1　最初の依頼に入れる要素

最初のプロンプトは、必要に応じて次の要素を含めます。

1. **目的**：何を実現したいか。
2. **材料**：AIに渡す文章や情報。
3. **条件**：守ってほしい点、避けたいこと、出力形式。
4. **確認方法**：どんな結果なら役に立ったと判断できるか。

例えば、文章を整理したい場合は次のように書けます。

```text
目的：次の文章を、初めて読む人にも分かりやすく整理したい。
材料：ここに自分の文章を貼り付ける。
条件：
- 元の意味や事実を変えない。
- 情報が足りない箇所は推測で埋めず、未確認として示す。
- 重要な条件や注意点を削らない。
出力：整理した文章と、変更した点・判断に迷った点を短く示す。
```

毎回すべての項目を埋める必要はありません。今回の作業に必要なものだけを使います。

### 6.2　依頼内容が曖昧なら、AIに相談する

やりたいことが決まっていても、AIへの頼み方が分からない場合は、完成版のプロンプトを一度に求めず、相談しながら具体化します。

```text
私は「〇〇をやってみたい」と考えていますが、依頼内容をまだ具体化できていません。
いきなり完成案を出すのではなく、目的・条件・使える材料を整理するために、
一度に一つずつ質問してください。
私の回答を受けて、最後に試せる小さな依頼文を作ってください。
不明なことを勝手に決めず、未確認として残してください。
```

質問が多すぎると感じたら、必要な質問を三つ以内に絞るよう頼んでも構いません。相談の目的は、立派なプロンプトを作ることではなく、まず試せる依頼文を一つ作ることです。

### 6.3　小さく試し、結果を記録する

一度の依頼で大きな成果を完成させようとせず、短い文章や一つの作業など、結果を確認できる範囲から始めます。期待と違った場合は、何が不足していたかを一つ選んで条件を加えます。詳しい反復改善の手順は、運用マニュアルで扱います。

AIの回答だけで事実や操作結果を確定せず、重要な情報は公式案内や実際の画面で確認してください。試したプロンプトと結果は、第7章の「AI試行記録」に必要な範囲で残します。

### この章の確認

- [ ] 目的・材料・条件・確認方法を必要な範囲で整理した。
- [ ] 曖昧な点はAIと相談して具体化した。
- [ ] まず試せる短いプロンプトを一つ作った。

次章では、小さなテーマを実際に試し、結果を経験として残します。

## 第7章　小さなテーマを試し、経験として残す

### この章の目的

ここまでで、AIを使うための基本的な準備、記録を保存する場所、目的と条件を整理する方法を用意しました。この章では、それらを使って小さなテーマを一つ試し、結果を自分の経験として残します。

ここで目指すのは、最初から大きな成果を完成させることではありません。「何を試したか」「何が起きたか」「次に何を変えるか」が分かる記録を一つ作ることです。

### 7.1　今回試すテーマを一つ選ぶ

まず、今の自分が試してみたいことを一つ選びます。数時間かかる大きな計画ではなく、結果を見て良し悪しを判断できる大きさにします。

例えば、次のようなテーマです。

- 自分が書いた短い文章を、意味を変えずに読みやすくする。
- 作業メモを、次回も使える手順に整理する。
- 興味のあるテーマについて、無料で試せる方法を調べ、確認先を整理する。
- 自分の経験を、初めて読む人向けの説明に書き直す。

テーマを選んだら、次の三点を書きます。

- **やりたいこと：** 今回、何を実現したいか。
- **今回の範囲：** どこまでできれば試行を終えるか。
- **確認基準：** 結果の何を見て、役に立ったか判断するか。

例えば「文章を読みやすくする」なら、範囲は「段落一つを整理する」、確認基準は「意味が変わっていないこと、重要な情報が残っていること、初見で理解しやすいこと」とできます。

### 7.2　使うAIと無料利用の条件を確認する

テーマが決まったら、その作業に合いそうなAIを選びます。AIを一つに決め打ちせず、文章の整理、調査の補助、案の比較など、今回の目的に合うものを選びます。

使い始める前に、公式の案内や実際の画面で次を確認します。

- 無料で今回の作業を試せるか。
- 利用回数・容量・機能などに制限があるか。
- 入力した情報がどのように扱われるか。
- 必要な機能やファイル形式を使えるか。

無料枠や画面、利用条件は変わることがあります。過去の記録やAIの説明だけで現在の条件を決めず、確認した日と確認先を記録します。無料で試せる範囲が足りない場合は、課金を前提にせず、作業を小さくするか、別の無料手段を検討します。

### 7.3　入力する情報を整える

AIへ渡す前に、材料を確認します。今回の目的に不要な情報は渡さず、個人情報、パスワード、アクセストークン、Cookie、非公開の認証情報などは入力しません。実際のデータを使う必要がない場合は、架空の例や機密情報を除いた抜粋で試します。

次に、第6章で整理したプロンプトを使い、目的・材料・条件・確認方法を伝えます。最初から長い指示を作る必要はありません。小さく試して、結果を確認できる形にします。

### 7.4　一回試し、結果を確認する

プロンプトを入力したら、結果をそのまま採用する前に、最初に決めた確認基準と照らし合わせます。

- 目的に沿った結果になっているか。
- 元の情報や重要な条件が保たれているか。
- 事実のように書かれた未確認情報が混じっていないか。
- 実際に使う場合に、危険な操作や望まない公開につながらないか。

必要な事実やサービス仕様は、公式情報や実際の画面など、適切な情報源で確認します。AIが「できた」と答えたことと、実際に確認できたことを区別します。

結果が期待どおりでなくても、試行は失敗として捨てず、どこが違ったかを記録します。問題が分かったら、第6章の方法でプロンプトの条件を一つだけ変え、必要な範囲で再試行します。何度も試すこと自体を目的にせず、今回の範囲で得られたことを残します。

### 7.5　試行記録を作る

試行が終わったら、次のひな形で記録します。AIとの会話全文を保存するだけでなく、後から読み返したときに、目的・実際に行ったこと・結果・次の一歩が分かるようにします。

```markdown
# AI試行記録

## 実施日
YYYY-MM-DD

## 今回の目的
何を実現したかったか：

## 試した範囲・確認基準
どこまで試すか：
何を見て結果を判断するか：

## 使用したAI・利用条件
ツール名：
無料利用の条件・制限：
確認日・確認先：

## 実際に行ったこと
入力した材料：
使用したプロンプト：
実行した手順：

## 結果
実際に得られたもの：
確認基準に照らした結果：

## 分かったこと・未確認
うまくいった点：
期待と違った点：
まだ確認できていない点：

## 次に試すこと
次回に変えること、または次の小さなテーマ：
```

記録には、必要な範囲でプロンプトと結果を残します。ただし、秘密情報や他人の個人情報、保存する必要のない会話内容をそのまま転記しないでください。公開を考える場合は、記録をそのまま公開せず、個人情報・権利・未確認情報を確認してから公開用に整えます。

### 7.6　保存先を決め、保存結果を確認する

第3章・第5章の判断表に従い、この記録の正本を一つ決めます。個人の作業記録は非公開の保管先に置き、公開してよい手順やサンプルだけを公開用リポジトリへ移します。Dropboxは、必要に応じて保管・受け渡し用に使います。

保存後は、正しいアカウントとフォルダーにファイルがあり、開いて内容を読めることを確認します。保存に失敗した場合は、元ファイルを残したまま、アカウント・保存先・容量・通信状態を確認して再試行します。原因が分からない場合は「未完了」と記録し、保存できたことにしません。

### 7.7　次の一歩を一つだけ決める

試行記録の最後に、次の行動を一つだけ書きます。例えば、次のような選択肢があります。

- 今回のプロンプトを少し直して、別の短い材料で試す。
- 公式情報を確認し、未確認だった点を埋める。
- 今回の手順を、初めての人でも再現できる説明に整える。
- 似たテーマを試し、結果の違いを記録する。
- いったん終了し、今回分かったことを整理する。

すべてを一度に進める必要はありません。一つの試行から得られた経験を次の試行につなげることで、自分に合う使い方や再利用できる手順が少しずつ蓄積されます。

### 7.8　この章の確認

- [ ] 今回試すテーマを一つに絞った。
- [ ] 目的・範囲・確認基準を書いた。
- [ ] 使用するAIの無料利用条件を確認した。
- [ ] 入力する情報から秘密情報や不要な個人情報を除いた。
- [ ] 結果を確認基準と照らし合わせ、未確認事項を区別した。
- [ ] 実際の操作・結果・問題・次の一歩を記録した。
- [ ] GitHubとDropboxの役割を分けて保存を確認した。
- [ ] 次に試すことを一つ決めた。

この章で作った試行記録が、次の挑戦の出発点になります。試行を継続して管理する方法や、記録を再利用しやすくする方法は、運用マニュアルで詳しく扱う範囲です。初版のセッティングマニュアルでは、まず一度試し、経験を残すところまでを目指します。
