## 第1章　AIで試したいことを、続けられる形で始める

### この章の目的

AIを使って何かを実現したいと思ったとき、最初から大きな仕組みを作る必要はありません。まずは、やってみたいことを一つ選び、小さく試し、その結果をあとから読み返せる形で残すところから始めます。

このマニュアルでは、生成AIの利用から作業環境の準備まで、無料で始められる方法を基本にします。有料プランや有料サービスが必要な手順を、当然の前提にはしません。

この章を終えると、次のことができる状態を目指します。

- AIで試してみたいことを一つ決められる。
- 作業に使う道具と、それぞれの役割を区別できる。
- 最初の小さな試行と、結果の記録方法を決められる。

### 1.1　最初に「実現したいこと」を一つ選ぶ

「AIで何かできないかな？」という段階でも構いません。最初から完成形や専門的な計画を決めず、少し試せば結果を確かめられる題材を選びます。

たとえば、次のような始め方があります。

- 自分の考えをAIと相談し、整理してみる。
- 日々の作業の一部を、AIでやりやすくできるか試す。
- AIとの対話や試行錯誤を記録し、あとで読み返せるようにする。
- 自分が試した方法を、他の人にも伝えられる形にまとめる。

ここで選ぶのは、長期計画ではなく**最初に試す一歩**です。うまくいくかどうかが分からなくても、結果を確認できる大きさにします。

#### 準備シート

次の項目を埋めてください。決まっていない項目は、空欄のまま、または「未定」として構いません。

| 項目 | 記入内容 |
|---|---|
| 試したいこと | 何をやってみたいか |
| なぜ試したいか | 興味、期待、実現したいこと |
| 最初の一歩 | 10〜30分程度で試せそうな作業 |
| 結果の見分け方 | 何が分かれば試した意味があるか |
| 残しておきたい記録 | AIの回答、実際の結果、気づき、失敗など |
| 今回はやらないこと | 最初の試行では扱わない範囲 |

**記入例（例示であり、効果を保証するものではありません）**

| 項目 | 記入例 |
|---|---|
| 試したいこと | AIとの相談内容を、あとで読み返せる記録にする |
| なぜ試したいか | 以前に試したことや、うまくいった方法を忘れたくない |
| 最初の一歩 | 短い相談を一回行い、要点をテキストファイルに残す |
| 結果の見分け方 | 後から読んで、相談内容と結論が分かる |
| 残しておきたい記録 | 相談の目的、試したこと、結果、次に試すこと |
| 今回はやらないこと | 自動保存や複雑な自動化の構築 |

### 1.2　道具の役割を分ける

このマニュアルでは、道具を一つの万能な仕組みとして扱いません。それぞれに役割があります。

| 道具 | このマニュアルでの役割 | 注意点 |
|---|---|---|
| 生成AI | アイデアを広げる、相談する、文章や手順を考える | 回答が正しいとは限らない。重要な事実は別途確認する |
| チャットの記録 | 何を相談し、どんな回答を得たか残す | 会話だけでは、実際に操作した結果まで証明できない |
| Markdownファイル | 経験や手順を、あとで読めるテキストとして残す | どのファイルが正式な原本か分かるようにする |
| GitHub | ファイルの変更履歴や、作業の区切りを管理する | 公開リポジトリに秘密情報や個人情報を置かない |
| Dropbox | ファイルを保管・同期するために使う | Dropboxにあるコピーが、必ずしも正式な原本とは限らない |

初めからすべての機能を使う必要はありません。まずは短い試行とテキストの記録を行い、必要に応じて管理方法を整えていきます。後続の章で各道具の準備と連携を扱います。

### 1.3　AIを選ぶときに確認すること

生成AIは、名前が違うだけで同じ使い方ができるとは限りません。利用できる機能、無料プランの上限、ファイルやリポジトリへのアクセス範囲などは、サービスや時期によって異なります。

利用を始める前に、少なくとも次を確認します。

1. 無料プランで、今回試したい作業ができるか。
2. 利用回数やメッセージ数などの制限があるか。
3. ファイル添付、長い会話、外部サービス連携などが必要か。
4. 入力する情報を、そのサービスに送ってよいか。
5. 制限に達したとき、作業を中断・記録して後で再開できるか。

無料枠の制限に達しても、すぐに有料契約する必要はありません。作業を記録して待つ、入力を小さく分ける、別の無料手段で代替できるか検討する、といった選択肢があります。ただし、別サービスへ移る場合も、機能や情報の扱いが同じとは限らないため確認してください。

### 1.4　最初の相談をしてみる

準備シートに書いた「最初の一歩」を、AIに相談してみます。目的や制約が曖昧なまま大きな作業を依頼するのではなく、まず小さな作業に区切って相談します。

次のテンプレートをコピーし、角括弧の部分を書き換えてください。

```text
目的：
[今回、実現したいこと]

今回やること：
[最初の一歩として試す作業]

今回はやらないこと：
[対象外にする作業]

使えるもの・制約：
[無料プランであること、使えるファイル、時間など]

完了の判断：
[何が分かれば今回の試行を終えられるか]

回答の希望：
- 手順を小さく分けて説明してください。
- 事実、提案、推測、未確認事項を区別してください。
- 不明な点を事実のように断定せず、必要なら質問してください。
- 実行や外部への変更が必要な場合は、操作前に説明してください。
```

このようにAIへ渡す依頼文を、ここでは「プロンプト」と呼びます。最初から完璧なプロンプトを作る必要はありません。回答を見て、足りなかった条件や誤解された点を相談し、少しずつ改善します。

AIの回答をそのまま実行するのではなく、まず内容を読み、今回の目的と合っているか確認してください。アカウント設定、ファイルの削除、公開、権限変更など、影響のある操作は、内容を理解し、必要な承認を得てから行います。

### 1.5　試した結果を短く残す

試行が終わったら、成功・失敗にかかわらず、次の項目をテキストで残します。

```text
# 試行記録

日付：
今回の目的：
実際に試したこと：
得られた結果：
自分で確認できたこと：
AIの回答だけで、まだ確認できていないこと：
うまくいかなかった点・制約：
次に試したいこと：
```

「AIがこう答えた」と「自分で実際に確認できた」は別の情報です。両方を分けて書くことで、後から読み返したときに、何が分かっていて何が未確認なのかを判断しやすくなります。

記録は、最初から整った報告書にする必要はありません。短い箇条書きで十分です。大切なのは、後から自分が読み返して、試したことと結果を思い出せることです。

### この章の確認

次の項目を確認してください。

- [ ] 試したいことを一つ選んだ。
- [ ] 最初の一歩と、結果の見分け方を書いた。
- [ ] 道具ごとの役割を区別できる。
- [ ] AIへの相談で、目的・範囲・制約・完了の判断を伝えた。
- [ ] AIの回答と、自分で確認した結果を区別して記録した。
- [ ] 未確認事項や次に試すことを残した。

まだ全部できていなくても、失敗ではありません。分からなかった項目を記録し、それ自体を次の作業にしてください。

**次章では、AIを継続して使うための利用環境と基本ルールを整えます。**


## 第2章　AIの利用環境と基本ルールを整える

### この章の目的

第1章で決めた「試したいこと」を、AIとの対話で少しずつ進められるようにします。ここでは、特定のAIサービスの画面設定を網羅するのではなく、どのAIを使う場合にも役立つ準備と、作業を安全に進める基本ルールを整えます。

無料プランの機能・利用上限・外部サービス連携は、サービスや時期によって変わります。実際に使う前に、現在の画面と公式の案内で確認してください。この章では、確認していない上限値や機能を固定の事実として扱いません。

### 2.1　AIに任せる役割を決める

AIに「全部任せる」と考えると、何を頼んだのか、何を自分で確認すべきかが曖昧になります。最初は、今回の作業でAIに手伝ってほしい役割を一つか二つ選びます。

- **発想を広げる**：やってみたいことの候補や別の方法を出してもらう。
- **整理する**：自分の考え、メモ、試行結果を読みやすくまとめてもらう。
- **手順を考える**：作業を小さな段階に分け、各段階の確認方法を提案してもらう。
- **文章やコードを作る**：下書きや例を作ってもらい、自分で内容と動作を確認する。
- **レビューする**：抜け、矛盾、危険、未確認事項を指摘してもらう。

役割は途中で変更して構いません。ただし、作業の目的まで変わった場合は、記録に変更理由を書きます。AIが提案しただけの内容と、実際に採用した内容を混同しないでください。

### 2.2　作業を始める前に、条件を伝える

AIへの依頼文を「プロンプト」と呼びます。長く書くこと自体が目的ではありません。AIが判断するために必要な条件を、分かる範囲で伝えます。

最低限、次の項目を用意します。

1. **目的**：何を実現したいか。
2. **今回の範囲**：いま頼む作業は何か。
3. **対象外**：今回は何をしないか。
4. **制約**：無料プラン、使える道具、時間、扱ってはいけない情報など。
5. **完了の判断**：何ができたら、この作業を終えられるか。
6. **確認方法**：結果をどのように確かめるか。

次のテンプレートを使えます。

```text
目的：
[実現したいこと]

今回の作業：
[いま進めたい小さな作業]

今回の対象外：
[いまは扱わないこと]

制約：
[無料プラン、使用できる道具、時間、情報の扱いなど]

完了の判断：
[どの状態になれば今回の作業を終えるか]

確認方法：
[結果をどう確かめるか]

回答のルール：
- 確認できた事実、提案、推測、未確認事項を区別してください。
- 不明な点は断定せず、作業に影響する場合は質問してください。
- 実行前に、外部への変更や取り消しにくい操作の内容を説明してください。
- 私の承認が必要な操作は、承認を得る前に実行しないでください。
- 最後に、実施したこと、確認できたこと、未完了事項、次の一手を分けて示してください。
```

最初の回答が目的に合わなかった場合は、プロンプトを最初から作り直す必要はありません。「どこが違ったか」「どの条件を追加すべきか」をAIに相談し、必要な部分だけを直します。こうして、試した内容と結果に合わせてプロンプトを育てます。

### 2.3　AIの回答を確認する

AIの回答は、読みやすく自信のある文章でも、間違いや古い情報を含む場合があります。特に、アカウント設定、料金、利用上限、権限、公開手順、コマンド、外部サービスの仕様は、回答だけを根拠に確定しないでください。

回答を受け取ったら、次の順で確認します。

1. 自分が依頼した目的と範囲に合っているか。
2. 前提としている機能・画面・ファイルが、実際の環境に存在するか。
3. 事実として書かれた内容に、確認可能な根拠があるか。
4. 操作した場合の影響や、失敗した場合の戻し方が分かるか。
5. まだ確認できていない点が、明示されているか。

確認できないことは「未確認」と記録します。AIが「完了した」と説明したことと、実際に操作が成功したことも別です。必要に応じて、画面、ファイル、実行結果などを自分で確認します。

### 2.4　外部に影響する操作は分けて扱う

AIとの相談、実行する操作、結果の確認を一つのものとして扱わないでください。特に、次の操作は、内容と影響を理解してから進めます。

- ファイルやフォルダーの削除・上書き
- アカウント、権限、認証情報の変更
- リポジトリやWebサイトへの公開
- 外部サービスへの送信や連携
- 有料契約、購入、課金につながる操作
- 元に戻すことが難しい操作

作業を依頼する前に、AIに「実行せず、まず手順と影響だけ説明してください」と伝える方法もあります。外部に影響する操作を実行する場合は、操作対象、変更内容、期待する結果、失敗時の対処を確認し、必要な承認を得てから行います。

また、パスワード、アクセストークン、秘密鍵、セッション情報などの認証情報を、通常の相談文や記録ファイルに貼り付けないでください。公開リポジトリに置いてはいけない情報や、サービスに送信してよいか分からない情報は、入力を止めて扱いを確認します。

### 2.5　無料プランの制限に備える

無料で続けるためには、制限がないことを期待するのではなく、制限に達しても作業を失わない準備をしておきます。

1. 利用中のサービスで、現在の利用上限やリセット条件を確認する。
2. 長い作業は、目的・決定事項・未完了事項を途中で記録する。
3. 添付ファイルや長文が必要な場合は、本当に必要な範囲に絞る。
4. 制限に達したら、無理に続けず、記録して再開できる状態にする。
5. 別のAIに切り替える場合は、機能や回答傾向が同じだと決めつけず、必要な前提だけを渡して結果を確認する。

無料枠の制限を避けるためだけに、記録や確認を省略しないでください。利用可能な機能や制限は変わるため、具体的な数値や対応機能を本文や記録に書く場合は、確認日と確認元も残します。

### 2.6　AIごとの使い方を固定しすぎない

AIサービスごとに、利用できる機能や制限、得意・不得意があります。複数のサービスを使う場合は、同じ依頼をそのまま渡すのではなく、目的に合う役割を決めて使います。

筆者自身の使い分け例としては、ChatGPTの無料利用では画像の貼り付けをできるだけ避け、ドラッグ選択によるコピー＆ペーストなど、テキスト中心でやり取りする方法があります。Claudeは無料利用の上限に達しやすいと感じているため、行き詰まったときに使う予備の手段として温存しています。Geminiは、Claudeが使えない場合などに別の視点を得るための確認役として使うことがあります。

これは筆者の利用経験に基づく例であり、すべての利用者・時期に当てはまる性能比較ではありません。実際に利用するときは、自分の無料枠、作業内容、回答の質を確認し、自分に合う役割分担を記録してください。どのAIも、最終的な正しさを保証するものとして扱わないことが大切です。

### 2.7　作業を再開できる記録を残す

作業を中断する前、または一区切りついたときは、次の項目を残します。会話の全文を毎回まとめ直す必要はありません。次に何をすればよいかが分かる情報を優先します。

```text
# AI作業の区切り記録

目的：
今回の作業：
今回決めたこと：
採用しなかった提案と理由：
実際に確認できた結果：
未確認のこと：
未完了のこと：
次に行う一手：
再開時に最初に確認するファイル・画面：
```

記録をAIに作成してもらう場合も、内容を確認してから保存します。AIが以前の会話を覚えていることを前提にせず、必要な決定事項と現在の状態を記録から再現できるようにします。後続の章では、記録をファイルとして管理し、GitHubなどで変更履歴を扱う方法を説明します。

### この章の確認

- [ ] 今回AIに手伝ってもらう役割を決めた。
- [ ] 目的、作業範囲、対象外、制約、完了の判断を伝えた。
- [ ] 回答の事実・提案・推測・未確認事項を区別した。
- [ ] 外部に影響する操作と、通常の相談を分けた。
- [ ] 無料プランの制限に達しても再開できる記録を用意した。
- [ ] 作業を中断するとき、未完了事項と次の一手を残せる。
