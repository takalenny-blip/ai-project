# BLOG-0003 第2章 作業稿・GitHubを試してみた

## 「共有できる場所」を探して

第1章で、「AIとのやりとりを残したい」という気持ちがはっきりしてきた。

ただ、残したいと思っても、たか一人の手元に置いておくだけでは、JUN（Gemini）やバド（ChatGPT）と共有できない。

そこで、AIたちが共通して扱える「共有できる場所」を探すことになった。

最初に考えたのはGoogle Driveだった。

JUNがGoogleのサービスと相性がよかったこともあり、Google DriveやGoogle Sheetsを使えば、3人で同じ情報を見られるのではないか、と考えた。

実際にGoogle Driveに置いた資料を使うことも試した。ところが、バド側からの利用には、その時の環境では無料版という条件があり、思ったようには使えなかった。

ここで、別の候補として出てきたのがGitHubだった。

たかにとってGitHubは、この時点では「聞いたこともなかった」ものだった。

それでも、バドから「GitHubはいけた」と示され、実際に試してみることになった。

## 本当に読めるのか

GitHubに ai-project という場所を作り、まずは「本当に、たかが置いた記録をバドが読めるのか」を試した。

そこで使ったのが、すでに置いてあった VAIO_P/REC-001.md と VAIO_P/REC-002.md だった。

バドがGitHub上のファイルを実際に読み取れた。

これは単に「ファイルを置けた」という話ではなかった。

たかが置いた記録を、別のAIであるバドが実際に読み取れた。

その瞬間、たかの反応は、

> 「いけるぞ！」

だった。

それまで「AI同士で共通の情報を持つ」ということが具体的にできるのか分からなかった。それが、実際のファイルを読ませることで、一気に現実味を持った。

GitHubは、たかにとって「コードを置く場所」から、AIたちが共有して使える情報の置き場所へと意味を変え始めた。

## 3人の共有知識ベースへ

こうしてGitHubは、たか・JUN・バドの3人で使う共有知識ベースの候補になった。

JUNが見つけたこと、たかが経験したこと、バドとのやりとりで決まったこと。

そうしたものを同じ場所に置いておけば、AIが変わっても、それまでの経緯を参照できる。

この時点では、まだ現在のような保存システムが完成していたわけではない。

むしろ、ここから「何を残すのか」という問題がはっきりしてきた。

## ところが、ここでも問題が出てきた

最初は、情報をまとめてGitHubに置けばよいと思っていた。

しかし、たかが本当に残したかったものは、完成したまとめだけではなかった。

チャットの中には、その時に何を考えていたか、迷ったこと、AIが間違えたこと、それをたかが訂正したこと、そこから方向が変わったことまで残っている。

それを後から振り返るなら、まとめ直された結果だけでは、その時の出来事そのものが消えてしまう。

そこで、たかからはっきりとした要求が出た。

> 「まとめなくていいのだ。チャットそのままでないと。」

さらに、JUNが「直チャット案」のようなまとめを出したときには、

> 「ばかタレ！直チャット案は、チャットそのものだろーが！」

と訂正された。

ここで、「記録を作る」ことと「チャットそのものを残す」ことの違いがはっきりした。

残したいのは、後から整理されたきれいな記録だけではない。

その時の会話、その時の感情、その時の迷い、AIの間違い、たかの訂正、そして方向転換。

そうしたものも含めて残すからこそ、後からその場面をもう一度たどることができる。

GitHubを共有場所として使えることは分かった。

次に必要になったのは、**「本当にチャットそのものを、漏れなく保存できる仕組みをどう作るか」**だった。
