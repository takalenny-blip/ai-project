# 1.5. GitHubに決めても、すぐには「使える状態」にならなかった

ここは記事でかなり重要な材料。

GitHubを使うことにした後も、「GitHubに置けば終わり」ではなかった。

2026-09-07の記録では、バドが最初は検索で該当リポジトリを特定できず、その後 `takalenny-blip/ai-project` を確認している。

さらに、リポジトリの中に
- `docs`
- `指針等`
- `直チャット`
- `経験ログ`
があることを再確認し、「共有情報庫」としての使い方を組み直している。

つまり、GitHubは「採用決定→完成」ではなく、

**探す → 読めるか試す → フォルダを整える → 何をどこに残すか決める → AI同士が同じものを読めるようにする**

という試行錯誤を伴っている。

さらに2026-09-14には、GitHubとVAIO Pをバドが混同する問題も起きている。

> 「GitHubとvaiopと連携してるの？別物では？」

これに対してバド自身が、

> 「GitHubとVAIO Pは別物だ。」

と訂正している。

この出来事も重要。

GitHubを正本として扱う現在の感覚から見ると当たり前に見えるが、当時は「GitHub上にあるもの」と「実機にあるもの」の境界すら、AI側が間違えることがあった。

だからこそ後の運用では、
- GitHub上の事実
- 実機で確認した事実
- 未確認事項
を分ける必要が生まれた。

ここは「GitHubの便利な機能紹介」ではなく、**実際に使いながら、AIにも人間にも分かる形へ整えていった過程**として残す。

AIとの会話
↓

↓
経験として整理

↓

↓

という循環になった。

つまりGitHubは、単なる保管庫ではなく、
「経験を次の経験につなぐ装置」
になっていった。

この表現は現時点では記事案上の仮説。最終本文では一次資料との照合後に採否を判断する。
