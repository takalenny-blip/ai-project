# VAIO P 現状台帳

更新日：2026-09-07

## 目的

VAIO Type PをPhase 3「実運用環境」の基盤として整備するため、過去に確認した情報と、現在の実機確認が必要な情報を分離して管理する。

この台帳では、過去ログから確認できた事実を「既知情報」とし、現在値が必要なものは「要再確認」とする。過去情報を毎回ゼロから調査し直さない。

## 1. 既知情報（過去資料から確認）

| 項目 | 内容 | 根拠・扱い |
|---|---|---|
| 対象機 | VAIO Type P / VGN-P70H/W | 過去のJUN直チャットで確認された機種名。現在値として再確認は不要。 |
| ストレージ | 導入前に既存HDDの状態確認、SSD換装を検討した | EXP-0000000020およびJUN直チャットに記録済み。 |
| VAIO Type Pのストレージ方式 | 1.8インチHDD、PATA方式に関する調査・検討を実施 | 過去のSSD換装調査として記録済み。ただし実機の現在装着状態とは区別する。 |
| Debian | VAIO Type PへのDebian導入・初期環境構築を実施 | EXP-0000000020に記録済み。 |
| Firefox ESR | 既に構築・軽量化作業を進めている | 現在の作業を壊さないことを最優先とする。詳細な現設定値は今回未確認。 |
| プロジェクト上の位置 | Phase 3「VAIO P実運用環境」 | マスタープラン・JUN向け指示書に基づく。 |

## 2. 今回の実機確認が必要なもの

過去情報を否定するためではなく、「2026-09-07現在の実機ベースライン」を確定するために確認する。

### A. OS・アーキテクチャ

- `cat /etc/os-release`
- `uname -m`
- 必要なら `uname -a`

確認目的：現在実際に起動しているDebianとCPUアーキテクチャを確定する。

### B. CPU・RAM・Swap・ディスク

- `lscpu`
- `free -h`
- `swapon --show`
- `lsblk -o NAME,SIZE,TYPE,FSTYPE,MOUNTPOINTS`
- `df -h`

確認目的：低リソース環境としての実容量・空き容量・Swap・ストレージ構成を確定する。

### C. ネットワーク

- `ip -br link`
- `ip route`
- `ping -c 3 1.1.1.1`

確認目的：インターフェース、経路、外部通信を確認する。設定変更は行わない。

### D. Python

- `python3 --version`
- `which python3`

確認目的：自動化プログラムを載せる基礎環境の確認。

### E. Git

- `git --version`
- `git config --global --get user.name`
- `git config --global --get user.email`

確認目的：Git利用環境を確認する。認証情報・トークンは表示・保存しない。

### F. ホームディレクトリ

- `pwd`
- `find ~ -maxdepth 2 -type d | sort`

確認目的：既存環境を把握し、今後の `apps / data / logs / config / work` 等の配置を決める材料にする。

### G. 常駐・自動起動

- `systemctl --type=service --state=running --no-pager`
- 必要に応じて `ps -ef`

確認目的：既存の常駐処理やリソース使用要因を把握する。

### H. Firefox ESR

今回は設定変更をしない。

- Firefox ESRの現在の動作を維持する。
- プロファイル削除、再作成、設定初期化などは行わない。
- 必要な場合だけ、後で設定値・プロファイル位置を確認する。

## 3. 今回は調べなくてよいこと

- 過去に確認済みの事項を、同じ理由だけで何度も調べ直すこと。
- DIGA自動取得の実装。
- cron/systemd timerの導入。
- 新しいパッケージのインストール。
- Firefox ESRの再設定。
- GitHubへの認証設定変更。

まず現在状態を確定し、その後に必要な変更だけを決める。

## 4. 判断ルール

1. 過去資料に事実がある場合は、まずそれを既知情報として扱う。
2. 現在値が変化している可能性があるものだけ再確認する。
3. 過去情報と現在の実測値が違った場合は、どちらかを勝手に削除せず、時点の違いとして記録する。
4. 推測と実測を混同しない。
5. 不明なものは「不明」と記録する。
6. 変更を伴う作業は、現状確認後に別途判断する。

## 5. 次の流れ

```text
過去資料（バドが確認）
        ↓
既知情報と再確認項目を整理
        ↓
JUNが実機で必要項目だけ確認
        ↓
たかが結果を確認
        ↓
バドが現在台帳を確定
        ↓
必要な変更だけ設計
        ↓
小さく実施・検証
```

## 6. この台帳の位置づけ

これは一回限りの調査メモではなく、VAIO Pの運用基盤を管理するための基準資料とする。

環境変更が発生した場合は、変更前後の事実を追記・更新する。ただし過去の経験そのものを消さず、必要に応じて経験ログや直チャットから経緯を追えるようにする。
