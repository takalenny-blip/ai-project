# 大手術設計 2026-09-15

## 目的

ai-projectの「現在状態が複数箇所に分散し、手動同期とAIの自己規律に依存する」構造を、一次記録を壊さず、機械的に検証できる構造へ改修する。

## 現状棚卸し

確認した問題は次の7点。

1. BUD・現在の引き継ぎ・直チャットに現在状態が重複し、手動同期が必要。
2. 自然言語ルールに依存する部分が多く、既知の失敗を機械的に止められない。
3. 直チャット連番が手動管理で、欠番・衝突・日跨ぎ管理が発生する。
4. `scripts/search_direct_chat.py` がGitHub Contents APIで多数ファイルを個別取得し、未認証レート制限に到達した。
5. 公開リポジトリの秘密情報保護が自己申告中心。
6. EXP/RECと一次記録の追跡性・検索性が弱い。
7. GitHub Actions / Issuesによる継続的な機械検証が不足。

## 設計原則

- 一次記録は不変資産として扱う。
- 現在状態は構造化データを基礎にする。
- BUDは現在状態を読むためのダッシュボードとして残す。
- 現在の引き継ぎは現在状態のビューとして扱う。
- 旧ファイル名は移行のために改名しない。
- 機械判定できる規則はスクリプト/CIへ移す。
- 判断が必要な内容はAI/たかの判断領域として残す。
- VAIO Pでは長文手入力を前提にしない。
- GitHub Contents APIの大量個別取得を通常検索経路にしない。

## 採用する改善

### A. 現在状態

`docs/現在状態.json` を構造化された現在状態の基礎として追加。BUDはダッシュボード、引き継ぎは再開ビューとする。

### B. 直チャット命名

新規保存はタイムスタンプ方式を採用可能とする。旧連番ファイルはそのまま残す。旧方式と新方式の混在を許容する。

### C. 検索

通常検索はローカルcloneの `git grep` / `rg` を第一候補とする。GitHub APIは必要時の補助経路とし、大量個別取得を避ける。

### D. 安全

保存前検査とCI検査で、メールアドレス、電話番号、認証情報、Cookie、セッション情報、APIキー等の混入を検出する。

### E. 機械的ガード

命名、重複、リンク切れ、現在状態の整合性を自動検査する。自然言語ルールだけで「守るはず」としない。

### F. EXP/REC

一次記録へのパスを可能な限り明示し、検索不能をデータ不存在と扱わない。追跡できない記録は未特定として残す。

### G. GitHub Actions / Issues

まずCIで安全性・整合性を検査する。Issuesは運用上必要な課題だけを整理し、作業の正本をIssueに移さない。

## 一括改修の順序

1. 現在状態を構造化。
2. BUD・引き継ぎを現在状態に合わせる。
3. 直チャット命名ルールを新旧共存型へ変更。
4. 検索スクリプトをAPI大量取得型から改善。
5. 保存前の秘密情報検査を追加。
6. CIの機械検査を追加。
7. EXP/RECの追跡性を点検。
8. Actions / Issuesを整理。
9. 全体検証。

## 完了条件

- 現在状態が構造化データで確認できる。
- BUDと引き継ぎが現在状態と一致する。
- 旧直チャットを壊さず、新方式を使える。
- 通常検索がGitHub API大量個別取得に依存しない。
- 秘密情報検査が自動実行可能。
- 命名・重複・リンク・状態整合性の機械検査が実行可能。
- 変更後にGitHubから主要ファイルを読み戻して確認できる。
