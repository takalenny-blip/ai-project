# 現在化・旧情報ガード

このファイルは `rules/運用ルール.md` を補助し、現在資料に古い「現在状態」「次の一手」「未完了事項」が残ったまま、次回AIが過去の作業を現在の命令として再実行することを防ぐためのガードである。

## 原則

1. **現在資料は追記だけで更新しない。** 現在状態が変わったら、旧状態を現在欄から削除・置換する。
2. **古い計画と履歴を分離する。** 過去に実施した計画・失敗・判断は一次記録や履歴として残してよいが、現在資料の「次の一手」「未完了」に残してはならない。
3. **完了・中止・保留になった作業は現在の未完了一覧から除去する。** 必要なら「履歴・完了事項」側へ移す。
4. **作業レーンを変更したら、旧レーンの次工程を新しい現在の次工程として残さない。** 旧レーンが予備ルートなら、その位置づけを明示して現在工程から切り離す。
5. **同期対象を更新する。** BUDと引き継ぎなど、現在状態を再開判断に使う資料を変更した場合、古い現在情報が残っていないか確認し、必要なら同一処理内で置換する。
6. **次回起動時に迷わせる情報を優先して除去する。** 「昔は次にこれをやる予定だった」という情報より、「今は何をやるか」が一意に読める状態を優先する。
7. **保存後の状態値を同期する。** 直チャット等の保存処理で現在値が変わる項目（最新保存番号など）がある場合、保存だけで完了とせず、現在資料の同じ値を実体に同期する。

## 更新時の必須確認

現在の次の一手を変更したときは、少なくとも次を確認する。

- 新しい次の一手が現在資料にある。
- 旧い次の一手が現在資料の「次の一手」「未完了」「現在の作業レーン」に残っていない。
- 旧作業を残す必要がある場合は、履歴・完了事項・予備ルート等、現在命令として読まれない位置に移されている。
- BUDと引き継ぎの現在状態が一致している。
- 古い情報を残すことが必要な場合でも、「履歴」であることが明確である。

## 保存後の状態値同期チェック

直チャット等を新規保存した場合は、保存処理とは別に次を確認する。

1. 実際に保存された最新ファイル名・連番を確認する。
2. BUD・引き継ぎ等に記載された同じ状態値を、その実体へ同期する。
3. 同期後に読み戻し、保存実体と現在資料の値が一致していることを確認する。
4. 一致しない場合は保存完了・現在化完了として扱わず、同期を是正する。

## 今回の適用

2026-09-15、BUDを「本来の工程＝DiMORA自動化」「トラブル対策＝予備ルート」に分離した際、`docs/引き継ぎ/現在の引き継ぎ.md` に残っていたJUN相談・一次記録検索を現在の次工程から除去し、現在の次の一手をDiMORA自動化へ同期した。

同日、直チャット保存後に最新保存番号が014のまま残っていた問題を確認した。保存ファイル自体は015・016まで存在していたため、これは保存失敗ではなく、保存後の現在資料への状態値同期漏れと判断した。以後は、**「保存実体 → 現在資料の状態値同期 → 読み戻し一致確認」までを一続きの現在化チェック**として扱う。

この事例を、**「新しい情報を書き足すだけでは現在化にならない。古い現在情報を消す／履歴へ移すところまでが更新」**という運用上の確認例と、**「保存だけでは現在化は完了しない。保存実体と現在資料の状態値を同期する」**という確認例とする。
