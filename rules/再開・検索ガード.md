# 再開・検索ガード

このファイルは、`rules/運用ルール.md` の運用を補助する、再開・検索時の最小限のガードである。

## 目的

検索失敗やセッション再開を理由に、すでに確認済みの事実・完了事項・既知の失敗条件を無意味に再調査・再実行することを防ぐ。

## 絶対原則

1. 一次記録・ファイルが存在することを確認済みなのに検索でヒットしない場合、「存在しない」「まだ調べていない」と断定しない。
2. 検索に失敗した場合は、可能ならローカルclone、直接ファイル名指定、既知のパスなど、別の到達経路を優先する。
3. `BUD.md`、最新の引き継ぎ、実際の直近ユーザー発言で確認済みとされている事実を、検索失敗だけを理由に未確認へ戻さない。
4. 既知の失敗条件が確認済みなら、同じ条件を理由なく再実行しない。
5. ユーザーが現在のGUI状態を明示した場合、その状態を現在状態として扱い、すでに完了したGUI操作をゼロから案内し直さない。
6. VAIO Pでは手入力困難・コピー＆ペースト不安定を前提とし、長文手入力を必要とする手順を基本案として出さない。

## トリガー

- 検索結果が出ない。
- GitHub API・検索サービス等が制限・失敗する。
- セッション再開時に過去資料と現在状態の不一致が疑われる。
- ユーザーが「もう調べた」「そこは開いている」等、現在状態を明示する。

## 必須行動

- まず現在の正本と既知の確認済み事項を前提にする。
- 検索経路だけが失敗している可能性を切り分ける。
- 可能なら別経路で一次記録へ到達する。
- 到達できない場合は「未到達」と記録し、「未存在」とは扱わない。
- 新しい事実がない限り、同じ調査を最初から繰り返さない。

## 完了条件

検索失敗時に、(1) データ不存在と断定していない、(2) 既知事項をリセットしていない、(3) 利用可能な別経路を優先した、または到達不能を明示した、の3点を満たす。

## 検証例

`python3 scripts/search_direct_chat.py chromium` が一度成功した後にGitHub APIの `403 rate limit exceeded` が発生した場合、同じAPI方式を再実行せず、VAIO Pの `/home/taka/ai-project` ローカルcloneから検索する。
