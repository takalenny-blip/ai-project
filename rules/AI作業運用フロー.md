# AI作業運用フロー

## 目的

ルールを読んだだけで満足せず、日常の作業そのものに組み込み、保存・更新漏れや「保存したつもり」を防ぐ。

## 基本フロー

すべての作業は原則として次の順で進める。

1. **現在資料を読む** — BUD、AI_READ_MAP、CURRENT_STATE、現在のrules、現在の引き継ぎを確認する。
2. **完了条件を決める** — 今回何ができれば完了なのかを明確にする。
3. **関連更新を確認する** — 作業結果により直チャット、EXP/REC、CURRENT_STATE、引き継ぎ、関連資料、rules等の更新が必要か先に確認する。
4. **作業を実行する** — 調査、設計、文章化、実装、検証等を行う。
5. **保存する** — 必要なファイルを実際にGitHubへ保存・更新する。
6. **読み戻す** — 保存したファイルをGitHubから実際に取得し、内容を確認する。
7. **整合性を確認する** — 関連ファイルとの食い違い、ID台帳との不整合、未完了事項の漏れがないか確認する。
8. **完了を判断する** — 実体確認まで終わって初めて完了とする。

## EXP / REC

EXP/RECを作成・更新する場合は、次を一連の作業として扱う。

- EXP：EXP-IDを発行 → EXPを作成 → ID管理台帳を更新 → GitHubへ保存 → 読み戻し確認。
- REC：所属EXPを確認 → REC-IDを発行 → RECを作成 → ID管理台帳の最終REC-IDを更新 → GitHubへ保存 → 読み戻し確認。

ID発行・台帳更新・本体保存を別々の作業として忘れない。

## 直チャット

正式保存すると判断した場合は、原文を一次記録として保存する。要約・再構成した文章を直チャットの代わりにしない。

## クローズ

チャット終了時は、今回の内容を振り返り、直チャット、経験ログ、現在状態・引き継ぎ、関連資料、rules等の更新要否を確認する。必要な更新を実行し、GitHubへの保存後に読み戻し・整合性確認まで行ってからクローズする。

## 完了判定

**「保存処理を試みた」「保存したつもり」では完了としない。**

実際にGitHub上に存在することを確認できないものは、保存済み・更新済みとは報告しない。

## 判断に迷った場合

事実、バドの推奨、たかの最終判断を分けて扱う。必要な判断だけをたかに確認し、確認不要な作業はバドが進める。
