# 現在有効な運用ルール

このディレクトリは、過去の作業記録ではなく、現在有効な運用ルールを整理する入口。

## 重要ルール

1. たかを中心に、たか＋バドで進める。JUN・Claudeその他は必要な場合だけ使う。
2. 過去に誰が何を担当したかは、現在の固定役割を意味しない。
3. 直チャットは原文を基本記録とする。
4. 作業上の事実は可能な限りテキストで残す。
5. 画像は主記録ではなく補助記録として扱う。
6. 経験DBでは事実と推測を混同しない。
7. 過去の記録を現在の事実に勝手に書き換えない。
8. 重要な現在認識が変わった場合は、BUD.md / CURRENT_STATE等の現在資料を更新する。
9. **チャットを終了・リセットする前に、次のセッションが再開できる状態を `docs/引き継ぎ/現在の引き継ぎ.md` に残す。**
10. **次のセッションでは、引き継ぎと現在資料を確認する前に、過去ログだけを頼りに操作・実装を再開しない。**
11. **作業環境の制約・権限・利用できなかった手段も、次の判断に影響する場合は現在状態として引き継ぐ。**
12. **同一環境で既に失敗した操作は、原因や環境が変わらない限り無条件に再試行しない。別環境へ移す判断を優先して検討する。環境が変わった場合は、同じ操作を再検証してよい。**
13. **失敗・再試行注意を記録するときは、可能な限り発生日・対象環境と再試行条件を明記する。ある環境での失敗を、環境条件を確認せず全環境共通の禁止事項にしない。**
14. **過去ログの「次にやること」は歴史上の計画であり、現在の命令ではない。作業開始前に現在資料・引き継ぎ・実績を照合して「現在の次の一手」を再構成する。**
15. **「前回ログにある」「まだ未確認欄に残っている」だけでは、過去の操作を再実行しない。既実施結果、失敗条件、環境差、変更点、現在の必要性・優先度、再検証の合理的理由を確認してから判断する。**
16. **過去記録は、事実・過去の判断・過去の計画・完了・失敗／破棄・再試行条件・現在有効なルール・現在の次の一手を区別して扱う。**
17. **未完了／完了だけで判断せず、「当時未完了だが現在は不要」「失敗だが条件変更で再試行可能」「必要だが優先度が低く保留」を区別する。**
18. **現在の「次の一手」の基準場所は `docs/00_CURRENT_STATE.md` とする。** 引き継ぎの次回操作は再開補助情報としてCURRENT_STATEと整合させる。
19. **作業開始前に、対象環境・ツールが現在の最上位目標と一致するか、過去のゾンビタスクではないか、過去情報を現在へ持ち込む根拠があるかを確認する。不明確な場合は過去タスクを無条件に実行せず、たかへ確認する。**
20. **直チャットの原文は1ターン1ファイルで即時保存する。ファイル名は `YYYY-MM-DD_直チャット即時保存_連番.md` とし、連番を会話順序の正本とする。保存後はGitHubから読み戻して実在と内容を確認する。**
21. **経験・経緯・記事化・漏れ確認など、網羅性が目的の過去記録調査では、AIが主観で数件だけ読んで終了してはいけない。対象EXPのRECを実ファイルから全件列挙し、RECごとに直チャットの出所を追跡し、未特定・未読・除外理由をCoverageとして確認する。詳細は `rules/過去記録調査・追跡フロー.md` に従う。**

## AI作業運用フロー

作業の開始から完了まで、`rules/AI作業運用フロー.md` を横断的な標準手順として扱う。

基本は、現在化・決定ゲート → 作業開始前最終確認 → 完了条件の確認 → 関連更新の確認 → 作業実行 → GitHub保存 → 読み戻し → 整合性確認 → 完了判断、の順で進める。

過去ログ由来の候補作業は、現在の目的・環境・優先度・状態を確認してから採用する。過去の「次回アクション」には命令権を持たせない。

過去記録の網羅調査は、通常の段階読み込みとは別に `rules/過去記録調査・追跡フロー.md` を適用する。

特にEXP/RECでは、ID発行・本体作成・ID管理台帳更新・GitHub保存・読み戻し確認を一連の工程として扱う。保存処理を試みただけでは完了としない。

## セッション引き継ぎ

詳細ルールは `docs/引き継ぎ/README.md` を参照する。

引き継ぎは「過去ログの要約」ではなく、**次のバドが作業を再開するための現在状態票**として扱う。

最低限、以下を記録する。

- 今回やったこと
- 今回の完了条件
- 確定
- 未確定
- 未着手
- 失敗・再試行注意
- 次に最初にやる操作
- やってはいけない手戻り
- 関連資料
- 必要に応じて、作業環境の制約と別環境へ移す判断

現在の次の一手そのものは `docs/00_CURRENT_STATE.md` を基準とし、引き継ぎの次回操作はそこから矛盾なく再開できるようにする。

特に、すでに試して失敗した操作や、確認済みであるため再度調べる必要がない事項、当時未完了でも現在は不要になった事項を明示する。
