# DIGA自動化

更新日：2026-09-21

## 1. 位置づけ

DIGA自動化は、2026-09-21をもって**本線作業を断念**する。理由は、現行のバド単独運用ではDIGA/DiMORAの実機側の取得・操作まで完遂できず、継続すると同じ箇所で停滞してたかの時間を消費するため。

これはDIGA自動化そのものを否定する判断ではなく、**現在のバドで進められる範囲の限界によるプロジェクト上の断念**である。既存の検証結果、コード、試行錯誤、設計知識は削除せず、履歴・経験資産として保持する。

特に **「お気に入り・機種別制御・警告メール」** は、過去作業として終わったものではなく、**work_pc＋Dropboxを現在の作業基盤として、今後さらに自動化を進める対象**として扱う。

## 2. 現在までの蓄積

過去のDIGA関連の直チャット・作業ログには、次のような実作業・設計検討が残っている。

- DIGAの録画情報・予約情報の管理
- 複数台のDIGAを区別して扱うこと
- お気に入り情報の管理・連携
- 機種ごとの制御
- 予約の追加・変更・削除などの変化を扱う考え方
- 放送日時、曜日、チャンネル等の情報整理
- 条件に応じた警告・メール通知
- Google Sheets / GAS等との連携

これらは「Claudeが作ったもの」という分類ではなく、**たかの実運用から得られた設計知識・試行錯誤・再利用可能な経験資産**として扱う。

## 3. 断念後の扱い

- DIGA / DiMORAを現在の本線・next_stepとして提示しない。
- work_pc＋Dropbox、正規化、変更検知、CDP取得試行等の既存成果は履歴として保持する。
- 将来、実機側を扱える別の実行手段が成立した場合に再検討する余地は残すが、現在の作業としては進めない。

## 4. 今後の方向

work_pc＋Dropboxを現在の実運用・検証基盤として、DIGA/DiMORAから必要な情報を取得し、既存のGoogle/GAS運用と接続する。

```text
DIGA / DiMORA
      ↓
work_pc＋Dropbox
      ↓
取得・整理・変更検知
      ↓
Google Drive / Sheets / GAS
      ↓
録画管理・お気に入り連携・警告メール等
```

具体的な取得方式、認証方法、通信方式、実行頻度などは、work_pc上で実機検証しながら決める。現時点で未検証の事項を確定仕様として扱わない。

**VAIO PをDiMORA取得方式の現在の検証環境とする方針は廃止する。** VAIO Pで過去に得た環境差やChromium取得プローブ等は履歴として残すが、現在の作業手順には含めない。

## 5. お気に入り・機種別制御・警告メール

この領域はDIGA自動化の中でも重点対象。

過去ログで検討された事項を、今後の実装時に再確認する。

- 複数のDIGAを機種・デバイス単位で区別する
- お気に入り情報を必要な対象に対して扱う
- 対象機器に既存情報がある場合とない場合を区別する
- 予約・録画情報の変化を検知する
- 必要な異常・注意状態をメール等で通知する
- 過去に検討・実装したロジックは、そのまま信じるのではなく現行環境で再検証する

## 6. 現在と未来を分ける

### 現在確認できていること

- DIGA関連の自動化を過去に実際に検討・実装した。
- 複数台のDIGAを扱う必要がある。
- お気に入り・機種別制御・警告メールは、今後も自動化を進める重要テーマである。
- work_pc＋Dropboxを現在の検証・搬送基盤として使う方向である。
- DiMORAお気に入り一覧のHTML内に `GL_FAVPGM_DATA` があり、`record[]` にお気に入りデータが保持されていることを確認している。
- 「もっと見る」は、ページ内の `record[]` を10件ずつ表示するJavaScript処理であり、追加取得の通信先を探すことが主課題ではない。
- 現在使用している制限付きWindows PCでは、F12、Ctrl + Shift + I、Ctrl + U、およびChromeメニューからのDevTools操作が利用できない。
- 制限付きPCで同じブラウザ操作を反復せず、現在は**work_pc＋Dropboxで取得・解析の実証へ進む方針**である。
- VAIO P + Firefox ESRでの過去調査は履歴として保持するが、現行工程には含めない。
- 作業開始時は、過去ログの「次にやること」をそのまま現在の作業とせず、現在化・作業判断ゲートを通して現在の次の一手を決める。

### 今後検証すること

- **work_pcで認証済みDiMORAページを機械的に取得する具体的方法**
- `GL_FAVPGM_DATA.record[]` または等価な機械可読データの抽出実証
- 認証状態を安全に扱う方法
- work_pcからDIGA/DiMORA情報を取得する具体的方法
- 現在のDIGA実機・ネットワーク環境で利用可能な方式
- 取得データの形式と安定性
- 定期実行の頻度
- Google/GASとの最適な接続方法
- お気に入り・機種別制御・警告メールの具体的な現行仕様

## 7. 進め方

1. work_pc＋Dropboxの共通運用基盤を使う。
2. **現在化・作業判断ゲートを通したうえで、work_pcで小さなDiMORA取得テストを行う。**
3. 認証済みページと取得データの構造を確認する。
4. 実機から取得できる情報を確認する。
5. テキストで結果・エラー・設定・判断を直チャットへ残す。
6. 必要な結果をEXP/RECとして経験DBへ整理する。
7. 小さく自動化し、実際に動かす。
8. 動作確認後、録画管理・お気に入り・機種別制御・警告メールへ段階的に拡張する。
