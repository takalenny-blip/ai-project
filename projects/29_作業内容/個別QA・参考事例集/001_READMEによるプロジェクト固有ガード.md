# 001：AIにルールを守らせるには？ READMEを使ったプロジェクト固有ガード

- 記録日：2026-10-30
- 分類：個別QA・参考事例
- 状態：実装済み。実運用での継続検証はこれから
- 発想の起点：たか

## 1. きっかけ・問題

AIにルールや禁止事項を繰り返し伝えても、会話や作業の切り替わりで確認・適用が抜けることがある。毎回注意を繰り返すだけでは、同じもどかしさが残る。

今回の課題は、特定のプロジェクトで守るべき注意事項を、作業開始時と回答送信前に確認できる形にすることだった。

## 2. 問い・試行錯誤

- 会話中に注意を繰り返す以外に、ルールを作業手順へ組み込めないか。
- プロジェクト固有の注意事項を、そのプロジェクトの入口で確認できないか。
- ルールを文章として置くだけでなく、回答を送る直前に点検する仕組みにできないか。

## 3. 発想・解決策

**READMEをプロジェクト固有のガードとして使うアイデアは、たかが出した。**

プロジェクトのREADMEに、そのプロジェクト固有の注意事項と送信前ゲートを記載し、作業開始・再開時および回答送信直前に確認する構成にした。

今回のREADMEに設けた送信前ゲートは、次の4点を点検する。

1. 画像：明示許可があるか。許可が示せなければ画像関連の出力・処理を除く。
2. 依頼範囲：各段落が直近の指示に直接答えているか。
3. 過去状況：現在・完了済み等の主張に、今回確認した資料の根拠があるか。
4. 事実区分：確定事項・提案・未確認を混同していないか。

許可が必要な操作の許可が不明、参照資料を読めない、指示と過去の決定が矛盾する等の場合は、影響する作業を止めて確認する。

なお、全会話に適用する共通ルールは rules/運用ルール.md に置き、プロジェクトREADMEにはプロジェクト固有の注意事項を置く。共通ルールとプロジェクト固有ルールの役割を混同しない。

## 5. 結果・検証状況

- READMEの追加はPR #1253としてmainへ反映された。
- この後の作業では、作業再開時に共通ルールと対象プロジェクトREADMEを確認する運用を行った。
- 今回の会話では、画像を表示・検索・生成しないという禁止事項を維持して作業を進めた。
- これは実運用上の確認例であり、あらゆる状況で違反を完全に防げることを証明したものではない。

## 6. 残る課題・限界

- READMEに記載しただけで、ルール遵守が自動的・完全に保証されるわけではない。
- 作業開始時にREADMEを読み込むこと、送信前ゲートを実際の回答に適用することが必要。
- プロジェクトの規模・性質によって、必要な注意事項やゲートの強さは異なる。
- 実際の運用で、違反を防げたか、確認負荷が過剰にならないかを継続して確かめる必要がある。

## 7. 他の環境へ応用するときのヒント

この事例の価値は、READMEの文面をそのままコピーすることではない。

- まず、AIに何度も伝えているのに守られないことを具体的に特定する。
- その問題が起きるタイミング（開始時、作業中、回答送信前など）を考える。
- そのタイミングで必要な確認と行動を、プロジェクトの入口や作業手順に組み込む。
- 完了条件と、実際に機能したかを確かめる検証例を設ける。
- 実運用で問題が見つかったら、固定テンプレートを押し付けず、その環境に合わせて育てる。

**AIへのもどかしさを、注意の繰り返しだけで終わらせず、仕組みで解決しようとした一事例。**

note等で紹介する場合も、「これが唯一の正解」ではなく、課題・本人の発想・実装・検証・応用のヒントを伝える参考事例として扱う。
