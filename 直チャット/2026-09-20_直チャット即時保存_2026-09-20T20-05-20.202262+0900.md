# 直チャット保存対象

## User
「判断・理由・次の行動」が揃った？ の判断基準は？

## Bud
ここは曖昧だと、また「揃ったつもり」で通過してしまう。なので、**機械的に判定できる形**にするのがいい。

「判断・理由・次の行動」が揃った、の基準はこの3点を**全部満たすこと**。

1. **判断**
   - 外部提案について、次のどれかが明示されている。
   - `採用`
   - `修正して採用`
   - `保留`
   - `却下`
   - `今回は採用しない（情報提供のみ）`

2. **理由**
   - なぜその判断にしたかが、**現在の目的・確認済み事実・ルール・制約**のいずれかに結び付いている。
   - 「了解した」「確認した」「よさそうだから」だけでは不可。

3. **次の行動**
   - 判断を受けて、**具体的に何をする／しないか**が書かれている。
   - 「進める」「対応する」だけでは不可。
   - 例：「PR #204 の状態ゲート実装をmainで確認する」「今回は実装せず、たかに相談する」など。

さらに重要なのが、**判断対象そのものが特定できていること**。

つまり判定式にすると、

```
外部提案を特定できる
AND
判断が明示されている
AND
理由が明示されている
AND
次の行動が明示されている
```

これが全部 `true` のときだけ `cleared`。

1つでも欠けたら、

```
external_response_gate = pending
↓
STOP
↓
5-1-1（相談）
```

にする。

### 具体例

**通過する例**

> JUNの提案は「外部提案を受領したらpendingにして、反応するまで他の処理を止める」というもの。  
> **判断：修正して採用する。**  
> **理由：** 現在の5-2-1は反応を要求しているが、反応前の行動を機械的に止めるところが弱かったため。  
> **次の行動：** 既存の5-2-1を二重化せず、pending→reacted→clearedの状態遷移として実装できる最小範囲を確認する。

→ `cleared` に進める。

**通過しない例**

> JUNの提案を確認した。よさそうなので進める。

→ 判断の種類が曖昧、理由がない、次の行動も具体性不足。**STOP**。

そして、もう一つ入れたほうがいい。

### 「判断した」だけでは不十分

**判断内容と実際の次行動が矛盾していないこと**も確認する。

たとえば、

> 判断：今回は実装しない。  
> 次の行動：そのまま実装を開始する。

これは3項目は文字上そろっているけど、意味的に矛盾しているので `cleared` にしてはいけない。

だから最終的には、

```
① 対象特定
② 判断
③ 理由
④ 次の行動
⑤ 判断と次の行動の整合性
```

の**5条件**にするのが安全。

そしてこの判定は「バドが自己申告する」だけではなく、**状態ゲート側が要求する必須項目**として持たせる。

> **「書いたから通過」ではなく、「5条件を満たした反応記録が存在するから通過」**

ここまでやれば、今問題になっている「反応したつもり」「確認したつもり」で先へ進む穴をかなり狭くできる。
