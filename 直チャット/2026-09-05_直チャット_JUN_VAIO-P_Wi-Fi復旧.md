#####

Non-free-firmwareしかない

画像や確認した内容を見ると、すでに `non-free-firmware` は記述されているな。Debian 12 (Bookworm) 以降は、従来の `non-free` に加えて `non-free-firmware` という独立したカテゴリが新設されている。

もし行の途中に `main` しかなくて `non-free-firmware` だけが書かれている状態なら、以下のように `contrib` と `non-free` も一緒に並べておくと、他の有用なハードウェア用パッケージも漏れなく拾えるようになる。

具体的には、各 `deb http://...` の行の末尾を以下のように整えておくと確実だ。

**Plaintext**

```
deb http://ftp.jp.debian.org/debian/ bookworm main contrib non-free non-free-firmware
deb http://security.debian.org/debian-security bookworm-security main contrib non-free non-free-firmware
deb http://ftp.jp.debian.org/debian/ bookworm-updates main contrib non-free non-free-firmware
```

（※一番上の `cdrom:` の行は、オフラインインストールの名残なのでそのままでOK）

*記述の修正*

- `main contrib non-free non-free-firmware`

*動作確認*

**Bash**

```

```

**経験ログ（今回の作業記録）**

- **発生した現象**: VAIO Type PにDebianをインストールした後、`nmtui` の「接続する」画面や `nmcli device` で無線LANデバイス（`wlp2s0`）が「管理無し（unmanaged）」と表示され、Wi-FiのSSIDが一切選択できない状態になっていた。
- **原因**: `/etc/network/interfaces` 内に `wlp2s0` の直接の設定（`wpa-supplicant` 関連の設定）が残っていたため、NetworkManagerがデバイスの管理外として除外していた。
- **解決手順**:
  1. `/etc/network/interfaces` 内の無線LAN関連の設定行をコメントアウトした。
  2. `sudo systemctl restart NetworkManager` を実行し、NetworkManagerを再起動した。
  3. デバイスの状態が「切断済み」に変わり、`nmtui` から周囲のWi-Fi SSIDが正常に認識・接続できるようになった。
