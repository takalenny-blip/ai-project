# 直チャット即時保存

## 目的
ChatGPT上のたか↔バドの直チャットを、原文の一次記録としてGitHubへ残す。

## 現在の保存方式

- **1ターン1ファイル**を基本とする。
- ファイル名：`YYYY-MM-DD_直チャット即時保存_連番.md`
- 連番を会話順序の正本とする。
- 各ファイルは `[User]` と `[Bud]` の原文を保存する。
- **ユーザーがJUN・Claude等の他AIの回答本文を貼り付けた場合、その貼付回答も省略・要約・再構成せず、ユーザーが提示した原文をそのまま保存する。** 保存上は `[JUN]` 等、発言者が分かる形で区別する。
- 要約・再構成した文章を直チャット原文の代わりにしない。
- ターン発生時に可能な限り即時保存する。
- 保存後はGitHubから読み戻して、実在と内容を確認する。

## 読み込み方針

毎回すべての直チャットを読むことを前提にしない。

1. 現在資料・引き継ぎを先に確認する。
2. 通常の再開・現在確認では、必要に応じて直チャットの最新ターンまたは該当範囲を読む。
3. 過去の詳細が必要な場合は、連番・日付・テーマをたどって追加で読む。
4. **経験・経緯・記事化・漏れ確認など、網羅性が目的の調査では、通常の「必要な範囲」読みをそのまま適用しない。** `rules/過去記録調査・追跡フロー.md` に従い、対象EXPのREC全件を列挙してから、RECごとに関連する直チャットを追跡する。
5. READMEに記載されたファイルやAIが最初に選んだ少数ファイルだけを調査対象として扱わない。
6. 重要な現在状態・判断・失敗・次の一手はCURRENT_STATE、引き継ぎ、EXP/REC等にも整理する。

## 網羅調査の完了条件

網羅性が目的のときは、少なくとも次を確認してから調査完了とする。

- 対象EXPのRECを実ファイルから全件列挙した。
- 各RECの一次記録・関連資料への参照を確認した。
- 直チャット参照がないRECについても、日付・テーマ・本文・ファイル名等から候補を探索した。
- 候補となった直チャットを確認した。
- 特定できない一次記録、読まなかった候補、その理由を明示した。

**「3ファイル読んだ」「READMEに載っているファイルを読んだ」だけでは、網羅調査の完了とはしない。**

## 管理

- このREADMEは管理方針の入口であり、毎ターン更新しない。
- 個々の直チャットファイルが原文記録の正本。
- セッション単位の区切りや管理情報が必要になった場合のみREADMEを更新する。
- 完全なChatGPT会話本文を取得できない場合、未取得部分を推測・再構成して完全原文とは扱わない。
- **ユーザーが貼り付けた他AI回答についても、取得できた貼付本文を一次記録として保存し、欠落部分を推測して補完しない。**
