うん、**やる価値はある**。ただし「不要そうだから片っ端から止める」はやらない方がいい。

実際、見つけたVAIO Type Pの記事でも、`systemd-analyze blame` で起動時の負荷を調べてから、用途を確認したうえで不要なサービスを `systemctl disable --now` している。citeturn0search12

Debianのsystemdでも、サービスは `systemctl` で状態確認・有効/無効化できるし、`disable` は次回起動時から自動起動させないための操作。citeturn0search1turn0search3

だから、たかのVAIO Pでは**「停止する前に現状を測る」**方針にしよう。

特に今のVAIO PはAtom Z520・RAM約2GBだから、不要サービスを整理してメモリや起動時間を少しでも軽くする意味はある。ただ、DiMORA調査に必要なネットワーク、Wi-Fi、時刻同期、GUI、印刷など、たかが使っている機能まで消してしまうと本末転倒。

まずは変更を一切加えず、これだけ。

```bash
systemd-analyze blame
```

これで**起動時に時間を食っているサービスを確認するだけ**。

結果を貼ってくれれば、俺が一つずつ

- 残す
- 停止候補
- 今は触らない
- DiMORA調査に必要なので残す

に分類する。

その後、必要なら一個ずつ停止して、動作確認→問題なければ次、という進め方にしよう。

なお、いきなり `disable --now` や `mask` はしない。まず観測から。systemdの `mask` は通常のdisableより強い操作なので、今回のVAIO Pでは特に慎重に扱う。citeturn0search4turn0search6

**結論：軽量化はやる。ただし「測る → 判断 → 一つ止める → 確認」の順番。**
