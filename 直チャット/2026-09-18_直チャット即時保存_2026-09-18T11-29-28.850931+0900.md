# 直チャット保存（確認可能範囲）

保存範囲についての注記：
この保存は、「このチャットのはじめから」の完全な逐語録ではない。現在の会話コンテキストからバドが確認できる範囲のみを保存する。取得できていない冒頭部分を推測・再構成していない。

## このチャットで確認できる主なやりとり

### 1. 現在の保存方針
ユーザー：
「ここまでのやりとり、このチャットのはじめから、直チャットに書き込めるかい？」

バド：
完全な冒頭からの逐語保存は、現在取得できる会話範囲だけでは保証できないため、見えていない部分を推測して「全件保存」とはしない。確認できる範囲なら正規の直チャット保存経路で保存できる。

ユーザー：
「できる範囲でいいんだが。」

バド：
確認できる範囲を「このチャットで確認できた範囲の直チャット」として正規保存する方針を提示。テスト用PR #60は今回の保存とは別物として扱い、勝手にマージしないことも確認。

ユーザー：
「ok」

### 2. 直近までに確認されたGitHub保存経路の改善
正本リポジトリは `takalenny-blip/ai-project`。
`docs/現在状態.json` が唯一の正本で、`BUD.md` と `docs/引き継ぎ/現在の引き継ぎ.md` は生成ビュー。

直チャット保存は `scripts/save_and_currentize.py` を通す。
保存は、保存要求 → 保存ブランチ → 正本スクリプト → PR → CI → 承認 → merge → readback の順で確認する。

GitHub Actions が `GITHUB_TOKEN` で保存PRを作成すると、そのPRの `pull_request` ワークフローが `action_required` になる問題を調査した。
原因として、GitHubの仕様上、`GITHUB_TOKEN` で作成・更新されたPRのワークフローが承認待ちになることを確認した。

修正PR #59では、`.github/workflows/save-request-intake.yml` のPR作成認証を
`GH_TOKEN: ${{ github.token }}`
から
`GH_TOKEN: ${{ secrets.SAVE_PR_TOKEN }}`
へ変更し、Secret未設定時には明示的に失敗するチェックを追加した。

PR #59は承認後にmergeされ、mainの本番ワークフローへ反映された。

### 3. 本番経路テスト
`SAVE_PR_TOKEN` 未設定状態ではテスト保存が
「SAVE_PR_TOKEN repository secret is required.」
で失敗した。

ユーザーが `SAVE_PR_TOKEN` をRepository secretへ設定。

再テストでは保存PR #60が作成され、`Current state views` のCIが
`completed / success`
となった。
従来発生していた `action_required` は本番経路では再現しなかった。

ただしPR #60はテスト保存用で、現時点ではopen/unmerged。今回の「確認可能範囲の直チャット保存」とは別に扱う。

### 4. 保存・運用上の重要ルール
- 見えていない会話を推測して保存しない。
- 保存完了はPR作成だけではなく、CI、承認、merge、正本readbackまで確認して判断する。
- `docs/現在状態.json` を直接手編集しない。
- 生成ビューを直接手編集しない。
- GitHubを正本として扱う。
- 未確認・未完了のものを完了扱いしない。
- 外部AIの提案は事実と提案を分離し、採用・修正・保留・却下を明示する。
- 「次の一手」は提案であり、実行はユーザーの明示指示がある場合に限る。
